# GPT 自由创作统一使用 Key 管理

日期：`2026-08-04`
状态：已确认

## 目标

移除首页创建 GPT 自由项目时的专用 Key 和模型选择。Key 管理成为主 AI 连接配置的唯一用户选择入口；每个新 AI 请求在开始时读取当前激活的 Key/模型并固定任务快照。

## 已确认行为

- GPT 自由创作创建弹窗仅保留画幅和“先生成首镜供我确认”。
- 新项目不再写入 `aiBinding`。
- 已存在项目中的 `aiBinding` 不再参与运行时路由；切换 Key 管理后，后续新任务使用新的活动 Key。
- 正在运行的任务继续使用启动时取得的完整 Key 快照，不受中途切换影响。
- DeepSeek 可参与完整的自由 HTML 链路。自由视觉总监和自由视觉生成都是文本到 JSON/HTML 的调用；单镜与全片视觉审查均为本地 DOM/HTML 规则检查，不需要视觉接口。
- GPT 专项优化仍由当前活动 Key 的设置决定；项目级 `confirmFirstFrame` 继续保留。

## 兼容边界

- 不删除 Prisma 中既有的可空 `aiBinding` 列，避免为本次行为调整引入破坏性数据库迁移。
- 旧项目可直接继续使用；遗留绑定数据被忽略。
- 图片生成、Pexels、Tavily、TTS 和标准项目工作流不变。

## 验收标准

1. 首页 GPT 自由创作弹窗不请求或展示 Key/模型列表。
2. 创建 GPT 自由项目无需 `aiBinding`，且仍强制使用 HTML 类型。
3. GPT 自由项目所有 AI API 路由使用 Key 管理的当前活动 Key，并保持请求级快照。
4. 旧项目的 `aiBinding` 不再覆盖活动 Key。
5. README 不再描述项目级 Key 锁定，并明确 DeepSeek 可测试自由 HTML 文本生成链路。
6. 聚焦测试、完整测试和生产构建通过。

## 非目标

- 不改变 Key 管理的数据格式。
- 不新增第二套“视觉模型 Key”。
- 不删除数据库历史列或旧迁移。
- 不保证不同模型生成 HTML 的创意质量完全一致。
