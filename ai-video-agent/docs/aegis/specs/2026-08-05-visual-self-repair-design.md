# 截图驱动的逐镜视觉自修复设计

日期：`2026-08-05`

状态：`用户已确认设计；等待书面规格复核后制定实施计划`

## 1. 目标

为 HTML 分镜增加一个可选的“视觉自修复”能力。它在镜头生成完成后，以该镜多个动画阶段的渲染截图为主要证据、以该镜完整 HTML/CSS 为修复对象，调用支持图片输入的 GPT 独立修复 Agent，尝试改善画面可读性、构图、遮挡、空白和视觉层级。

该能力是优化助手，不是导出门禁：失败、超时、模型不可用或候选未改善时都保留原画面，不阻断预览或导出。

成功证据：用户主动开启开关后，任一新生成或内容变更的 HTML 分镜最多经历一次“截图审片 → 代码修复 → 截图复审”；只有复审确认改善且确定性安全审计未退化的候选被保存。关闭开关时不截图、不创建 Agent 任务、不调用视觉 API。

## 2. 已确认的产品行为

### 2.1 开关

- 用户可在工作台设置中启用“视觉自修复”。
- 新能力默认关闭，避免未经同意的图片上传和视觉 API 消耗。
- 选择保存在浏览器 `localStorage`，下次打开工作台恢复上次值。
- 关闭只停止视觉自修复；既有 DOM 审计、手动质量修复、预览和导出流程维持原行为。

### 2.2 单镜 Agent 边界

- 每个 HTML 分镜是一个独立任务；任务只能读取和修改该镜的 HTML/CSS。
- 不修改大纲、旁白、标题、其他镜头、项目设置和项目级视觉风格。
- 同一 HTML hash 最多自动尝试一次。重新生成或用户编辑导致 hash 改变后，才允许新的尝试。
- 每镜最多一轮模型修复和一轮截图复审；不循环调用模型直到“看起来修好”。

### 2.3 截图与上下文

- 在动画 35%、70%、100% 三个时间点采样。0% 不参与，避免把正常的开场留白或入场前状态视为缺陷。
- 本地为三张截图计算内容密度，内容最丰富者为主截图；主截图是视觉判断的最高权重证据，其余截图是动画时序补充证据。
- Agent 请求包含：三张截图、当前镜完整 HTML/CSS、当前镜标题/旁白/画面提示词/SceneSpec/时长，以及主题、核心主张、视觉风格摘要、章节和分镜序号。
- 不传输整份大纲；当前镜语义切片和极短全片上下文足以保持语义和风格，且可避免跨镜干扰与额外延迟。

### 2.4 可修改与不可修改的内容

允许模型调整：位置、尺寸、间距、层级、颜色与对比度、可见性结束状态、动画时序，以及文字的换行、字号、行高、文本容器和衬底。

禁止模型调整：标题、旁白、屏幕事实、数字、单位、文字语义和顺序；也禁止删除/隐藏关键内容、通过降低透明度伪装修复、引入外部资源、网络请求、随机行为或不受控交互。

## 3. 运行时架构

```text
设置开关开启 + 当前镜 HTML hash 未处理
  → 质量运行器创建单镜视觉自修复任务
  → 隐藏渲染器在 35% / 70% / 100% 采样截图
  → 选出主截图，并构造单镜上下文与 HTML 输入
  → 视觉自修复 Agent（一次支持图片的 GPT 请求）
  → 返回候选 HTML
  → 安全清洗与信息保留验证
  → 重渲染相同三时点截图 + 确定性 DOM 审计
  → 视觉复审
  → 改善：保存候选和报告；否则：丢弃候选、保留原镜
```

现有 `PreviewPanel` 中的质量运行器仍是前端调度入口，负责候选选择、取消、状态显示与保存顺序。新的视觉自修复能力应抽成单一领域服务，避免继续把截图、提示词、API 协议、前后比较和 React effect 逻辑堆入同一组件。

现有 HTML 清洗、元素 ID 注入、重要信息保留断言、项目 Key 上下文和 AI 传输所有者必须复用；视觉自修复不得复制第二套 Key 解析、Responses 请求构造、SSE 解析或 HTML 安全校验。

## 4. 请求契约

视觉 Agent 使用已验证的 Responses 图片输入格式：一段结构化文本上下文加三项 `input_image`。每个视觉自修复 Agent 调用只有一次上游请求；不自动重试、不降级到 Chat Completions、不静默切换 Key 或模型。

提示词必须要求模型仅输出完整 HTML 文档。模型必须在修复前后保留：可见文本、`data-editor-id`、`data-editor-label`、`data-role`、本地资源路径、既有动画意图以及内容/事实约束。

模型输入中的截图 data URL 仅用于当前请求。客户端状态、服务端日志、质量报告和 API 错误中不得保存或回显 Base64 原文；可记录 MIME 类型、尺寸、字节数和 hash 等摘要。

## 5. 改善判定与回退

候选 HTML 必须同时满足以下条件才可保存：

1. HTML 通过现有安全清洗、结构验证和重要信息保留校验。
2. 重新运行的 DOM 审计没有新增 critical 问题，也没有相对原镜退化。
3. 截图复审认为候选相对于原镜有明确改善；主截图结论优先，辅助截图不得暴露新的严重动画过程问题。

不满足任一条件时，候选只存在于任务内存，随后丢弃；项目中继续使用原 HTML。此结果记为“未改善，保留原画面”，可供质量面板提示，但绝不阻断导出。

视觉模型不支持图片、模型调用失败、响应超时、取消、输出非 HTML 或审计无法完成时，都属于非阻断失败。任务结束且不保存候选，不触发旧的多轮 AI 修复回退路径。

## 6. 数据与 UI

现有质量报告需扩展一份版本化的视觉自修复摘要，而不是持久化截图本身：

- 输入/候选 HTML hash；
- 三个截图的摘要和 hash，以及主截图索引；
- 视觉审片与复审结论；
- 是否尝试/是否保存、失败类别和修复摘要；
- 开始、完成时间及当前质量审计版本。

质量面板和分镜条使用这些摘要显示轻量状态。该数据只说明本次自动优化的结果，不改变既有 HTML 质量门禁的权威性。

## 7. 兼容性与能力边界

- 仅 HTML 分镜适用；图片分镜、UI 场景和非 HTML 导出流程不接入。
- GPT 自由创作继续使用项目绑定 Key/模型；标准 HTML 工作流仅在当前配置支持图片输入时运行视觉 Agent。
- DeepSeek 及没有图片理解能力的模型永远不可承担视觉审片或视觉修复。此时显示“视觉模型不可用”，不调用其他配置作为隐式替代。
- 既有 DOM 审计和导出门禁保持为确定性安全边界；视觉结论是建议性优化信号，不获得阻断导出的权限。

## 8. 非目标

- 不做跨镜叙事重写、全片重新编导或素材替换。
- 不保存截图、模型原始输出、API Key 或推理内容到数据库或浏览器持久化存储。
- 不增加用户必须逐镜确认的候选图库或复杂任务管理 UI。
- 不对未启用开关的存量分镜进行后台补跑。
- 不将“审美偏好”变成不可导出的硬规则。

## 9. 验收标准

1. 默认关闭；开关变更后刷新工作台仍恢复最后一次选择。
2. 关闭状态下，质量运行器不会采样截图、创建视觉修复请求或调用 GPT。
3. 开启状态下，符合条件的单镜只采样 35%/70%/100%，并将内容密度最高截图标记为主证据。
4. 每个单镜任务传输截图、当前 HTML 和当前镜语义切片；不传输整份大纲，也不修改其他镜头。
5. 每个 hash 最多一次模型修复和一次复审；取消、超时和不可用模型均不产生第二模型调用或隐式模型切换。
6. 修复可改变文字排版，但不能改变受保护文本、事实、数字、单位、元素 ID 或本地资源。
7. 仅在视觉复审明确改善且 DOM 审计不退化时保存；否则项目 HTML 不变。
8. 视觉任务任何结果都不削弱既有导出门禁，也不增加新的导出阻断。
9. 截图 Base64 和模型敏感诊断不进入持久化报告、浏览器日志或用户可复制的错误体。

## 10. 设计依据与检查

### TaskIntentDraft

- Outcome：以截图为主、代码为修复对象的单镜视觉自修复，用户可控、轻量且非阻断。
- Success evidence：开关记忆、单镜隔离、三时点截图、一次修复/复审、只保存改善版本和非阻断失败均有自动化证据。
- Stop condition：实现、测试、README 更新和比例验证完成；不以真实 API 调用成功作为自动化测试前提。
- Risks：图像请求成本、截图采样性能、模型输出破坏信息、截图数据泄露和视觉审美误判。

### BaselineUsageDraft

- Required baseline refs：`AGENTS.md`、`README.md`、现有 `auto-optimize.ts`、`preview-panel.tsx`、`frame-quality-repair.ts`、`export-gate.ts`、`codex-responses.ts` 及既有图片输入设计。
- Cited in design refs：现有质量运行器/DOM 审计、HTML 保护链路、Responses `input_image` 传输和 DeepSeek 视觉能力限制。
- Missing refs：无阻断缺口；实施计划阶段需确认截图采集可复用的浏览器渲染路径和模型能力表示位置。
- Decision：continue。

### ImpactStatementDraft

- Affected layers：工作台设置、前端质量调度、截图采样、视觉 Agent、AI transport、质量报告、质量 UI、测试与 README。
- Canonical owners：质量运行器负责调度；视觉自修复领域服务负责单镜契约；既有 Responses transport 负责图片请求编码；既有 HTML 安全/审计层负责接受候选。
- Invariants：用户 opt-in、单镜隔离、文本事实保护、无截图持久化、无静默模型切换、视觉结果不阻断导出。
- Compatibility：既有 DOM 审计/手动修复/导出门禁不退化；开关关闭时保持当前行为。
- ADR signal：无。该设计复用既有 AI transport 与质量所有者，不引入公开接口、持久化 schema 或新的外部兼容契约。

### Architecture integrity

- Invariant：模型只提供单镜候选，浏览器审计与复审决定是否保存。
- Canonical owner：视觉修复不得成为第二个项目保存或 AI transport owner。
- Higher-level simplification：复用既有图片输入 Responses 编码、HTML 验证和 `frame-tunes/apply` 保存路径。
- Verdict：以一个视觉自修复领域服务承载新职责，避免在 React effect 或 API route 中复制业务规则。
