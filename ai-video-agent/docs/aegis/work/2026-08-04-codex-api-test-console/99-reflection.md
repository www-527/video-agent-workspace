# Codex-Compatible API Test Console — Reflection

- The central judgment was to create an isolated Responses-only reference path instead of adding more fallback behavior to the already complex legacy diagnostic path.
- Keeping SDK retries disabled and reporting a single request count makes failures attributable and gives future production changes a stable comparison point.
- Key secrets remain server-side; the browser receives only masked metadata and normalized bounded events.
- The 446-line dialog is cohesive and below the project's soft complexity threshold. Transport and route responsibilities live in separate 170-line and 92-line owners, avoiding new responsibility in the home page or legacy API-chat component.
