# 智能配图问题交接文档（低成本、无多模态方案）

## 1. 目的与边界

目标：让 HTML 视频的真实配图**符合分镜主题、主体和叙事用途**；当没有足够可靠的素材时，宁可明确使用原生 HTML 图解，也不能混入错误图片。

本轮不接入多模态/视觉大模型。原因是候选图逐张视觉审核成本高，且当前项目不能把 DeepSeek 当作视觉模型使用。方案只使用结构化分镜信息、英文检索词、Pexels 元数据、确定性规则和浏览器/服务端日志。

这个边界意味着：系统可以显著降低“牙医设备配到海上风电检修”这类明显错误，但不能承诺纯文本规则能够判断所有图片的审美、细粒度物件或隐含语义。

## 2. 已确认的故障证据

### 2.1 深海科研站故障排查指南

- 项目：`8d75301e-73b3-42e5-9b43-e4acc28f2d98`
- 第 7 镜目标：海上/深海运维中的盐雾腐蚀、狭窄空间和设备排查。
- 实际检索词：`professional equipment physical detail`。
- 实际验收图片：牙科设备，Pexels alt 为 `Detailed image of sterile dental equipment used in modern dentistry and healthcare settings.`
- 错误原因：筛选器只要求泛词命中；`equipment`、`detail` 足以让牙科设备通过，没有海洋/运维领域约束或医疗排除词。

### 2.2 海上风电场紧急检修：安全规范与故障处理

- 项目：`a1cacfc5-f605-4cdc-aacd-6affde48d63f`
- 第 6 镜是叶片、齿轮箱、发电机的检查清单，`assetStrategy: icon`、`visualRole: explain`，本应使用图解。
- 同一分镜却被写入 `realImagePriority: required`，触发了强制找图。
- 实际检索词：`modern workplace documentary scene`。
- 实际验收图片：巴格达办公室会议照片，和风电检修无关。
- 最终 HTML 未引用该图，已降级为正确的清单图解；图片文件成为孤儿文件。

## 3. 当前链路

```text
Director/Outline（AI，输出 SceneSpec）
  -> Deterministic Asset Planner（本地规则，决定是否找图和查询词）
  -> Asset Worker（Pexels 搜索、文本打分、下载）
  -> Visual Composer（AI，生成带 <img> 或原生图解的 HTML）
  -> Validator（本地规则，检查 HTML 是否引用本地图片）
  -> Preview / Render
```

相关实现：

- 规划：`src/lib/ai/real-image-planner.ts`
- 搜索/下载：`src/lib/pexels/smart-images.ts`、`src/lib/pexels/client.ts`、`src/lib/pexels/download.ts`
- 候选排序：`src/lib/pexels/scoring.ts`
- HTML 合成与图片引用校验：`src/lib/ai/html.ts`、`src/app/api/frames/html/route.ts`
- 浏览器生成事件：`src/hooks/use-frame-generation.ts`

## 4. 根因

### P0：结构化分镜契约可以互相矛盾

`assetStrategy: icon/chart/css-svg/typography` 本意是原生图解，但 `realImagePriority: required` 可以同时存在。现有逻辑会优先把 `required` 送入素材搜索，造成不必要且高风险的配图。

### P0：检索词缺少主题约束

多数中文分镜没有可直接使用的英文检索词时，会退化为通用词：

- `professional equipment physical detail`
- `modern workplace documentary scene`

这些词不能表达行业、场景、主体和排除范围。

### P0：下载即“验收”

候选排序只使用 Pexels 的 `alt`、尺寸、比例、摄影师和颜色。对于非人物素材，默认允许零个主体词命中；即使要求命中，也会接受 `equipment` 这样的泛词。

### P1：没有“错误图片优先拒绝”的策略

没有领域禁词、同义词组、最低相关性分数、最少关键概念覆盖率或主题一致性门槛。

### P1：HTML 合成失败会静默改成无图

带图版 HTML 未通过校验时，生成器会允许原生 HTML 重试。原先不会保存首次失败原因，导致“下载 1、验收 1、应用 0”很难诊断。

现已补充：已验收素材未被最终 HTML 引用时，通过 SSE 向浏览器控制台输出项目、分镜、素材路径和降级原因。

## 5. 目标设计（不使用多模态模型）

### 5.1 先决定“是否应该用照片”

新增 `AssetRequest` 归一化和冲突检查：

| 条件 | 行为 |
| --- | --- |
| `assetStrategy` 为 `icon`、`chart`、`typography`，且不属于真实案例/现场证据 | 强制 `useRealImage: false` |
| `realImagePriority: required` 与原生图解策略冲突 | 记录诊断并降为原生图解；不得搜索泛化替代图 |
| 真实案例、人物、具体设备、地点、自然现场 | 可申请真实素材 |
| 无法表达为具体英文主体和场景 | 不搜索，使用原生图解 |

`required` 的语义应改为“必须使用符合要求的真实素材；找不到则明确降级/阻断”，绝不能是“必须塞入任意照片”。

### 5.2 强制使用结构化英文检索契约

对每个计划检索的镜头，要求生成或规范化以下字段：

```ts
type AssetRequest = {
  query: string;                 // 3-10 个精确英文词
  fallbackQueries: string[];    // 1-3 个，不得比主词更泛
  requiredTerms: string[];      // 至少一个必须命中的领域/主体词组
  optionalTerms: string[];
  excludedTerms: string[];      // 例如 dental, dentist, hospital, office
  subjectType: 'person' | 'equipment' | 'place' | 'environment';
  purpose: string;
  imageRequired: boolean;
}
```

示例：海上风电检修

```json
{
  "query": "offshore wind turbine maintenance technician",
  "fallbackQueries": [
    "wind turbine gearbox inspection",
    "offshore wind farm repair equipment"
  ],
  "requiredTerms": ["wind", "turbine"],
  "excludedTerms": ["dental", "dentist", "hospital", "office", "meeting"],
  "subjectType": "equipment",
  "purpose": "建立风机现场检修语境",
  "imageRequired": false
}
```

实现建议：Director 在输出 `SceneSpec` 时直接给出这些英文信息；本地规划器只做格式校验、冲突修复和兜底，不负责把一整句中文猜成泛化英文。

### 5.3 收紧 Pexels 候选规则

在 `scorePexelsCandidates` 中新增硬过滤，过滤后再排序：

1. `alt` 命中任意 `excludedTerms`：直接拒绝；
2. `alt` 必须命中至少一个 `requiredTerms` 词组；
3. 泛词停用：`professional`、`equipment`、`detail`、`modern`、`scene`、`workplace` 不能单独构成通过依据；
4. 若候选 `alt` 为空、过短或不含任何主题词：拒绝；
5. 记录每张候选的通过/拒绝理由、命中词与分数；
6. 所有候选不合格时返回“无可靠素材”，不要下载第一张。

不应把“检索结果排名靠前”当作相关性证明。

### 5.4 图片合成必须可追踪

当 `imageRequired` 为真且已有验收图片：

- HTML 必须在 `visual-zone` 中引用每张本地路径；
- 首次失败后进行一次**仍带图**的定向重试，重试提示中包含缺失路径和校验错误；
- 第二次仍失败：保存原始输出、校验错误、素材路径和降级原因；
- 只有 `imageRequired: false` 时允许自动改为原生图解；
- 不得把“已下载”显示为“已应用”。

### 5.5 可观测性与用户反馈

每个素材请求应持久化：

- 分镜 ID、主题、检索词与备用词；
- 每个候选的 Pexels URL、alt、命中/排除词、分数和拒绝理由；
- 下载、验收、HTML 引用、最终应用四个独立状态；
- HTML 首次失败与重试的错误文本；
- 最终降级原因。

浏览器控制台诊断仅是开发辅助；工作台也应展示“为什么没有配图”，避免用户只能打开开发者工具排查。

## 6. 分阶段实施建议

### 阶段 A：阻止错误配图（低成本，优先）

1. 实现 `AssetRequest` 冲突检测：`icon/chart/...` 与真实图片优先级冲突时拒绝搜索。
2. 删除/禁用通用兜底词；无具体英文主题词时直接原生图解。
3. 加入 `requiredTerms`、`excludedTerms` 和泛词停用规则。
4. 候选全不合格时，不下载。
5. 补全持久化诊断和工作台提示。

预期：显著减少错误照片，代价是部分镜头会选择无图的 HTML 图解。

### 阶段 B：提高可用率（仍不使用多模态）

1. 让 Director 输出英文检索词、必须词与排除词，并在 JSON schema 中校验。
2. 为常见行业建立小型领域词库：风电、制造、医疗、金融、教育、办公等。
3. 使用 Pexels `alt`、URL slug 和摄影师信息共同评分。
4. 支持用户在分镜卡片中编辑检索词、排除词和“此镜不用照片”。
5. 为已被人工确认的素材建立按主题/主体复用缓存。

### 阶段 C：成本可控的人工闭环（可选）

1. 每镜展示 3 张候选缩略图与文字理由；用户一键选图或“全部不合适”。
2. 人工选择结果写入本地词库和主题缓存；后续同类题材优先复用。
3. 仅对人工标记为“高风险”或“无法判断”的少量镜头预留多模态审核入口，而非对全部候选调用。

## 7. 验收标准

### 功能验收

- `icon/chart/typography` 镜头不会因 `required` 标记而搜索无关照片。
- “海上风电检修”查询必须包含 `wind` 和 `turbine`；`office`、`dental`、`hospital` 候选必须被拒绝并显示原因。
- “深海科研站设备排查”查询必须包含 `underwater/deep sea` 或 `marine/offshore`，且牙科设备不能通过。
- 没有合格候选时，结果明确为“未找到可靠素材，使用原生图解”，不是“已验收”。
- 有验收图片而 HTML 未引用时，持久化首次失败原因、本地路径、重试结果和最终降级原因。

### 测试验收

- `real-image-planner`：覆盖策略冲突、无精确查询、图片比例和连续镜头限制。
- `scoring`：覆盖必需词、禁词、泛词、空 alt、URL slug 与阈值。
- HTML：覆盖带图重试、禁止静默无图降级、诊断事件。
- 端到端模拟：使用固定 Pexels fixture，验证错误候选不下载、正确候选被引用。

## 8. 不做的事情

- 不把 DeepSeek 作为图片理解或审核模型。
- 不将“关键词命中”宣传为视觉语义审核。
- 不以增加图片数量为目标；相关性优先于配图比例。
- 不在没有可靠素材时用办公室、医疗、通用设备照片填充实体镜头。

## 9. 交接入口

先从阶段 A 开始。建议改动顺序：

1. `src/types/index.ts`：增加 `AssetRequest` / 查询约束字段；
2. `src/lib/ai/real-image-planner.ts`：实现策略冲突检测和精确查询要求；
3. `src/lib/pexels/scoring.ts`：实现禁词、必需词和泛词过滤；
4. `src/lib/pexels/smart-images.ts`：持久化候选决策，拒绝不合格候选；
5. `src/lib/ai/html.ts` 与 `src/app/api/frames/html/route.ts`：保留带图失败原因，控制无图降级；
6. `tests/`：用深海科研和海上风电 fixture 做回归测试。
