# GPT 自由生成恢复交接文档

> 状态：待实施。本文只记录现状、判断和恢复方案；不要把它理解为已经完成的回退。
>
> 目标：恢复 GPT 在视频 HTML 分镜上的最高创作自由度，同时保留对可读性、越界、重叠、导出一致性的底线保护。

## 一、问题结论

用户反馈的核心不是“GPT 的模型能力不够”，而是当前实现把 `gpt-free` 工作流接入了和普通/DeepSeek 工作流相同的**标准结构化生成链路**。这属于过度修复。

为解决第一镜文字与背景混合、第二镜元素与字幕重叠、第八镜无意义图形等问题，当前实现将安全规则直接放进了 GPT 的创作前置条件。结果是 GPT 不能自由选择媒介、构图和信息密度，只能在保守的结构模板里作答，因此观感被拉低到与普通模型相近的水平。

原则应改为：

> **创作层保留自由；质量层只拦截实际故障。**

质量层可以拒绝不可读、越界、遮挡、无语义装饰、失效动画和未审计画面；不应预先规定 GPT 只能使用哪两种构图、画面最多几个对象或必须使用某个 DOM 角色。

## 二、当前生成链路

当前 `gpt-free` 项目生成 HTML 时的实际路径：

```text
项目 workflow = gpt-free
  → /api/frames/html
  → 读取选定 stylePreset，创建/写回 VisualContract
  → generateFrameHtml（标准结构化生成器）
  → 标准 HTML 校验、结构化质量审计
  → 服务端导出门禁
```

关键文件：

| 文件 | 当前职责 | 对 GPT 自由度的影响 |
| --- | --- | --- |
| `src/app/api/frames/html/route.ts` | 对所有 HTML 工作流调用 `generateFrameHtml` | `gpt-free` 已不再调用自由生成器 |
| `src/lib/ai/html.ts` | 标准生成器、自由生成器和 HTML 校验 | 标准生成器温度为 `0.45`；自由生成器仍在文件中但未被路由调用，温度为 `0.9` |
| `src/lib/ai/visual-contract.ts` | 创建全片视觉契约 | 契约含布局和对象数量等创作限制 |
| `src/lib/render/visual-audit.ts` | 全片结构审计 | 强制每镜恰好一个 `data-role="focal"` |
| `src/lib/quality/export-gate.ts` | 服务端导出门禁 | 对所有 HTML 帧使用标准结构校验 |

## 三、当前施加的限制

### 1. 只允许两种布局

`src/lib/ai/visual-contract.ts` 当前写入：

```ts
allowedLayouts: ['split', 'stack']
```

这会排除或显著压缩下列正当表达：全屏摄影、海报式排版、局部特写、拼贴、非对称构图、类型主导画面、模拟 UI、分层蒙版、舞台式群像等。

### 2. 每镜语义对象数被压到 4 个

同一契约当前包含：

```ts
maxSemanticObjects: 4
```

“画面不要杂乱”不等于“画面只能有四个对象”。对于对比、产品拆解、群像、流程、叙事转场等镜头，这个提示会促使模型把有效信息降维成空卡片或抽象线框。

### 3. GPT 被改走标准模板生成器

`route.ts` 目前统一调用 `generateFrameHtml`。该函数的系统提示包含：

- 标准 `text-zone` / `visual-zone` 几何区；
- `split` / `stack` 结构化布局约束；
- `SceneSpec`、主题 Token、导演计划、视觉锚点、完整 VisualContract；
- 默认温度 `0.45`，紧凑重试时降为 `0.35`；
- 标准 `validateGeneratedHtml` 通过后才接受结果。

虽然 `withGPTVisualFreedom()` 会附加“可以自由创作”的文字，但它排在这些硬结构约束之后，且与之冲突。实际效果是：提示词表面要求 GPT 自由，底层验收却只接受标准答案。

### 4. 一个视觉焦点被错误实现为固定 DOM 结构

`visual-audit.ts` 要求每镜恰好一个：

```html
data-role="focal"
```

“有清晰阅读重心”是正确的设计原则；“页面必须存在且仅存在一个固定角色标签”不是。后者会误伤双主体对照、多人关系、连贯过程、前后状态切换和全屏文字节拍。

### 5. 导出门禁仍假设所有 HTML 都是标准画面

`export-gate.ts` 对 HTML 帧调用 `validateGeneratedHtml`，并要求当前质量报告、HTML 哈希、审计版本和全片评分均通过。门禁本身是必要的，但它没有按 `workflow` 区分标准画面与 GPT 自由画面。

## 四、原本可用的 GPT 自由路径

`src/lib/ai/html.ts` 中仍保留：

```ts
generateFreeFrameHtml(...)
```

它的设计意图是：

- 使用 `FREE_FRAME_HTML_SYSTEM`；
- 允许 HTML、CSS、SVG、Canvas、自由排版、模拟 UI、抽象图形和不同构图；
- 不要求为兼容旧编辑器而添加 `data-role`、`split/stack`、卡片预算或节点图；
- 温度为 `0.9`；
- 以 `validateFreeGeneratedHtml` 做最小运行安全校验。

该函数目前仍在代码中，但已没有正常生产调用点。这是恢复 GPT 能力最直接的切入点，不需要重写全部生成系统。

## 五、必须保留的质量保护

以下保护是针对已发现的真实事故，应保留；只是要从“创作前置限制”改为“生成后质量检查”。

1. 字幕安全区：底部字幕区域不得承载关键画面信息。
2. 渲染安全：完整 HTML、无外部 URL/CDN、无随机数、无弹窗/用户交互、动画在镜头时长内结束并保持终态。
3. 可读性与越界审计：检查文字溢出、透明/不可见、元素越界、遮挡、资源加载失败等。
4. 多时点检查：当前 35%、70%、100% 动画时点的 DOM 审计应保留，防止只在动画中途或终态出错。
5. 服务端导出门禁：质量报告必须与当前 HTML 哈希和审计版本匹配，过期或未通过的画面不可导出。
6. 全片一致性：固定字体、颜色、光影/质感、动效气质和少量识别性母题。

不需要视觉识别 API；上述检查基于 DOM、几何、CSS 和生成时的结构化意图即可执行。

## 六、应该删除或改写的限制

| 当前规则 | 处理方式 | 替代原则 |
| --- | --- | --- |
| `allowedLayouts: ['split', 'stack']` | 从 GPT 创作提示中移除 | 每镜由叙事目的选择构图，整片避免连续复用同一种构图 |
| `maxSemanticObjects: 4` | 从 GPT 创作提示中移除 | 控制信息层级，而不是机械限制对象数量 |
| 强制唯一 `data-role="focal"` | GPT 工作流不再使用该硬校验 | 要求“阅读重心清楚”，允许双主体、群像和过程镜头 |
| GPT 统一调用 `generateFrameHtml` | 按 workflow 分支恢复自由生成器 | GPT 使用自由生成器，普通模型继续使用标准生成器 |
| GPT 使用标准 `validateGeneratedHtml` | 按 workflow 分支校验 | GPT 使用自由安全校验 + 渲染质量审计 |
| 把完整 VisualContract JSON 注入 GPT | 缩减为“视觉圣经” | 只传艺术方向和禁用问题，不传结构模板 |

## 七、目标架构

```text
                         ┌───────────────────────┐
                         │ 全片视觉圣经            │
                         │ 色彩 / 字体 / 质感       │
                         │ 母题 / 节奏 / 禁用问题   │
                         └───────────┬───────────┘
                                     │
                  ┌──────────────────┴──────────────────┐
                  │                                     │
       GPT 自由生成路径                           标准模型生成路径
       自由媒介、构图、密度                         split/stack 等受控几何
       高温度、镜头差异                             稳定、易编辑
                  │                                     │
                  └──────────────────┬──────────────────┘
                                     │
                         生成后质量层（共同）
                 可读 / 安全区 / 越界 / 遮挡 / 动画终态
                 审计版本与 HTML 哈希 / 服务端导出门禁
```

“视觉圣经”建议只包含：

- 主题 Token：颜色、字体、对比度、空间感；
- 视觉语言：例如“精密产品工坊、深色石墨、冷白标注、克制金属高光”；
- 2–3 个可重复的识别母题：例如细线标注、半透明材料层、计量刻度；
- 片内节奏：开场、解释、转折、结论分别应有何种能量；
- 禁止问题：无意义浮动图形、无语义连线、长段上屏、低对比文字、字幕区关键内容。

它不应包含固定布局列表、DOM 角色数量或对象数量上限。

## 八、实施步骤

### 步骤 1：拆分“视觉圣经”和“标准布局契约”

新增轻量类型，例如 `GPTVisualBible`。可复用 `VisualContract` 中的 `themeId`、`tokens`、`visualLanguage`、`prohibitedPatterns`，但不要把 `allowedLayouts`、`maxSemanticObjects` 传给 GPT。

### 步骤 2：在生成路由恢复 workflow 分支

在 `src/app/api/frames/html/route.ts` 中按 `project.workflow === 'gpt-free'` 分支：

- GPT：调用扩展后的 `generateFreeFrameHtml`；传入视觉圣经、风格提示、主题 Token、导演计划和视觉锚点。
- 普通 HTML 工作流：继续调用 `generateFrameHtml`。

`generateFreeFrameHtml` 需要扩展参数，以接收风格信息；不能恢复到“完全不理会用户已选风格”的旧状态。

### 步骤 3：让自由生成器接受艺术方向，不接受模板命令

更新 `FREE_FRAME_HTML_SYSTEM` 与其用户提示：

- 使用 GPT `open` 创作档或至少保持自由生成器的高温度（建议从 `0.85` 开始调参）；
- 明确每镜要与相邻镜头形成构图/媒介/节奏差异；
- 明确禁止无意义装饰，但允许有叙事功能的复杂画面；
- 保留字幕安全区和运行安全规则；
- 不出现 `split`、`stack`、`data-role`、对象数量预算等要求。

### 步骤 4：按工作流分离校验与导出门禁

- `reviewFrameArtifact`：GPT 使用 `validateFreeGeneratedHtml`；标准工作流使用 `validateGeneratedHtml`。
- `visual-audit.ts`：对 GPT 不再检查唯一 `data-role="focal"` 和标准布局标记；保留 `visualIntent`、文本安全、语义/重复性等适合自由画面的审计。
- `export-gate.ts`：按 workflow 选择结构校验器；仍必须检查质量报告状态、HTML 哈希、审计版本和全片分数。
- `stampVisualContract` 可保留为溯源标记，但不应作为 GPT 画面结构合格的条件。

### 步骤 5：重生成并逐帧验收

当前用户项目《Codex CLI 科普：安装前，先看权限》是旧链路产物，不能作为修复完成后的验收成片。恢复后应从分镜 HTML 开始重新生成，不必先改变口播或配音。

注意：重生成会调用用户配置的模型/配音服务并产生额度或成本，执行前应取得用户确认。

## 九、验收标准

### 画面层

- 每镜都有明确叙事动作和阅读重心，但允许多主体；
- 8–12 镜成片至少出现 4 类有意义的视觉语法，例如全屏图像、局部特写、产品/UI、类型节拍、对照、流程/数据；
- 同一构图不得连续使用超过 2 镜，除非是明确的连续动作；
- 不出现无语义图形、纯装饰连接线或为了填空而出现的图标；
- 字幕与主要信息不重叠，文字与背景具有足够对比，任何时点不得越界或不可见。

### 系统层

- GPT 自由镜头可以通过导出门禁，不要求 `split/stack` 或唯一 `data-role="focal"`；
- 普通/DeepSeek 工作流仍保持原有标准结构保护；
- 35% / 70% / 100% 时点审计照常工作；
- 未审计、审计过期、HTML 后改或存在严重问题的项目仍不能导出；
- 不增加视觉识别 API 依赖。

### 回归测试

至少补充并通过以下测试：

1. `gpt-free` 路由调用自由生成器，而非标准生成器；
2. GPT 生成提示含视觉圣经但不含 `allowedLayouts` / `maxSemanticObjects`；
3. GPT 自由构图可通过导出门禁；
4. 标准工作流仍会拒绝缺失 `text-zone` / `visual-zone` 的 HTML；
5. GPT 画面若存在越界、不可见文字或动画终态故障，仍会在质量审计或导出门禁被阻止；
6. 重新生成目标项目后，对第一、第二、第八镜做 35% / 70% / 100% 的截图人工复核。

## 十、当前验证与工作区注意事项

本轮“标准化质量门禁”改动曾通过：

- `npx tsc --noEmit`；
- `npm test`：96 个测试文件、539 项测试；
- `npm run build`：Next.js 生产构建。

这些结果证明当前代码可运行，不证明当前 GPT 创作体验正确。

当前工作区存在大量与本任务无关的未提交修改、删除和新增文件。恢复 GPT 能力时**不要**执行 `git reset --hard`、整体 `git checkout -- .` 或批量恢复文件。只修改本交接文档列出的相关文件，并在修改前用 `git diff` 核对局部差异。

## 十一、最终决策

推荐执行“**恢复 GPT 自由生成 + 保留生成后质量门禁**”，而不是回到完全无风格、无检查的旧 `gpt-free`。

这样既能恢复 GPT 的构图、媒介和镜头调度能力，又不会重新放行本次用户指出的文字混背景、字幕遮挡和无意义图形问题。
