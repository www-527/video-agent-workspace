## 1. 目标与最终效果

当用户在质量面板点击“重新修复”，或生成后自动优化触发同一条视觉修复链路时，对应分镜的缩略图立即进入：

```text
低饱和柔焦画面
+ 轻薄中性暗色蒙层
+ 一条低强度品牌色扫描光带
+ 居中的短状态文案“正在优化”
```

该效果要表达的是“AI 正在接管并分析这张画面”，而不是“卡片不可用”“内容丢失”或“页面被阻塞”。修复可能持续较长时间，因此视觉反馈必须克制、稳定，不能持续抢占用户注意力。

预期结构：

```text
┌─────────────────────────────┐
│ #3                    音频/状态 │  ← 清晰，不模糊
│                             │
│       原分镜缩略图            │
│     轻微柔焦、降饱和、降亮度    │
│                             │
│ ─── 低强度扫描光带 ───→       │
│          正在优化             │
└─────────────────────────────┘
│ 分镜标题（始终清晰、可读）      │
└─────────────────────────────┘
```

## 2. 设计原则

### 2.1 只处理缩略图画面层

必须模糊的内容：

- 图片缩略图；
- `HtmlThumb` 的静态终态缩略图；
- `StaticThumb` 占位画面。

不得模糊的内容：

- 分镜卡片外框与选中描边；
- 分镜标题；
- 分镜编号；
- 音频按钮；
- 仍然存在的质量问题徽标；
- 修复状态文案。

不要把 `filter` 加在整张卡片或缩略图最外层，因为 CSS `filter` 会连同编号、按钮和状态文字一起模糊。

### 2.2 克制的柔焦，不隐藏原画面

建议参数：

```css
filter: blur(2px) saturate(0.82) brightness(0.82);
transform: scale(1.025);
```

要求：

- 默认模糊强度使用 `2px`，允许在视觉验收后最高调整到 `3px`；不得使用 `6px+` 的强模糊。
- `scale(1.025)` 只用于覆盖模糊后可能露出的透明边缘。
- 缩略图预览容器必须保持 `overflow: hidden`。
- 原画面仍应足以辨认构图、主体和正在修复的是哪一个分镜。

### 2.3 中性蒙层，而非液态玻璃

深色工作台建议蒙层：

```css
rgba(10, 14, 20, 0.38)
```

日间主题建议蒙层：

```css
rgba(241, 245, 249, 0.44)
```

不要加入折射、噪点、液态玻璃、强白色高光、大面积透明毛玻璃或鼠标跟随效果。这些效果会降低小尺寸缩略图的可读性，也会增加多分镜并发时的渲染负担。

### 2.4 扫描光带

扫描光带是唯一持续运动元素：

- 光带有效宽度约为缩略图宽度的 `20%–30%`；
- 使用透明渐变，不画出清晰硬边；
- 单次循环建议 `1.9s`，允许在 `1.6s–2.2s` 范围内微调；
- 使用 `ease-in-out`，不要高频线性扫动或闪烁；
- 深色主题使用橙色 `#fb6d2d` 的低透明度版本；
- 日间主题使用当前蓝色主色 `#3b82f6` 的低透明度版本；
- 中央峰值透明度不高于约 `0.25`；
- 多个分镜同时修复时允许同步扫描，不要为每张卡片创建 JavaScript 定时器或随机延迟。

推荐用 CSS 自定义属性集中主题值：

```css
.studio-shell {
  --storyboard-repair-overlay: rgba(10, 14, 20, 0.38);
  --storyboard-repair-accent-rgb: 251 109 45;
}

html[data-theme='light'] .studio-shell {
  --storyboard-repair-overlay: rgba(241, 245, 249, 0.44);
  --storyboard-repair-accent-rgb: 59 130 246;
}
```

如果实施时发现主题 Token 已被统一调整，应优先让扫描光带跟随工作台实际生效的主题色，并在交付说明中记录最终取值；不得在多个选择器中散落重复色值。

### 2.5 状态文案

默认只显示：

```text
正在优化
```

取消已发出、正在等待当前步骤结束时可以显示：

```text
正在停止
```

不要在 `72px` 或 `128px` 宽的缩略图中显示“采样中”“视觉修复中”“终态验收中”“正在保存”等长阶段信息。完整阶段继续由质量面板展示。

不要为修复状态再加旋转 spinner。扫描光带已经承担持续反馈，spinner 与扫描同时出现会显得拥挤。

执行 AI 必须先核对以下位置：

| 修复请求、任务 ID、停止状态、质量运行状态 | `src/stores/studio-store.ts` | 作为修复蒙层唯一状态源 |

| 当前用户说明 | `README.md` | 功能完成后补充分镜修复反馈说明 |

现有事实：

- `qualityRepairRequests[frameId]` 在用户提交修复后立即存在，并在任务 `finally` 中清理，适合覆盖排队、采样、模型调用、验收和保存的完整生命周期。
- `qualityRuns[frameId]` 提供细分阶段和终态。
- `qualityRepairStops[frameId]` 能区分“正在停止”。
- `generatingFrames[frameId]` 是首次生成画面或旁白的状态，不等同于重新修复。
- 当前修复支持多分镜并发，因此所有判断必须按 `frameId` 独立计算，不能只看当前选中分镜。

## 4. 状态模型

### 4.1 活动状态集合

将以下 `FrameQualityRunState['status']` 视为运行中：

```ts
auditing
sampling
optimizing
visual_repairing
terminal_verifying
sampling_recheck
saving
cancelling
```

以下状态是终态，不应仅凭它们继续显示修复蒙层：

```ts
passed
saved
needs_review
unchanged
unavailable
cancelled
failed
```

在 `src/lib/quality/quality-ui.ts` 新增一个类型安全的统一谓词，例如：

```ts
export function isQualityRepairRunActive(
  status: FrameQualityRunState['status'] | undefined,
): boolean;
```

该函数必须由 `StoryboardStrip` 和 `QualityPanel` 共同复用，替换质量面板目前重复书写的活动状态判断，确保新增阶段时只有一个维护入口。不要修改任何状态的业务语义。

### 4.2 单镜修复显示条件

每个分镜计算：

```ts
const repairRequested = Boolean(qualityRepairRequests[f.id]);
const qualityRun = qualityRuns[f.id];
const repairRunning = isQualityRepairRunActive(qualityRun?.status);
const repairStopping = Boolean(qualityRepairStops[f.id])
  && (repairRequested || repairRunning);
const repairActive = repairRequested || repairRunning;
const showRepairOverlay = repairActive && !isGenerating;
```

说明：

- `repairRequested` 必须纳入判断，使用户点击后不必等待异步 Effect 启动就能看到反馈。
- 终态 `qualityRun` 会保留在 Store 中，不能因上一轮状态是 `passed` 或 `failed` 而永久显示蒙层。
- `qualityRepairRequests` 在任务完成后清理，蒙层应自然退出。
- `qualityRepairStops` 可能保留到下一次请求，但没有活动请求或运行状态时不得单独显示蒙层。

### 4.3 首次生成与修复的优先级

同一分镜不允许同时渲染“生成中”和“正在优化”两套视觉层。

优先级：

```text
首次生成 generatingFrames
  > 重新修复 qualityRepairRequests / qualityRuns
  > 普通缩略图
```

当修复请求正在排队、但该分镜仍处于首次生成时，继续显示现有“生成中”遮罩；首次生成结束后，如果修复请求仍有效，再切换到“正在优化”。

### 4.4 不新增模拟进度

不要显示百分比，不要根据动画循环次数推算进度，也不要在前端设置超时后自动结束蒙层。真实任务何时完成只能由现有 Store 状态决定。

## 5. DOM 与层级改造

### 5.1 缩略图内容增加独立包装层

在 `storyboard-strip.tsx` 中，把图片、`HtmlThumb` 和 `StaticThumb` 三个互斥分支统一包进一个只承载画面的容器，例如：

```tsx
<div
  data-testid="storyboard-thumbnail-content"
  className={cn(
    'storyboard-thumbnail-content absolute inset-0',
    showRepairOverlay && 'storyboard-thumbnail-content--repairing',
  )}
>
  {/* img / HtmlThumb / StaticThumb */}
</div>
```

最终类名可以调整，但必须满足：

- 画面分支只有一个共同包装层；
- `filter` 和 `scale` 只落在这个共同包装层；
- 缩略图父容器保持 `relative` 和 `overflow-hidden`；
- 不改变图片 `object-cover`、HTML 缩略图终态和画布宽高比。

### 5.2 修复蒙层为相邻层

修复层不要使用整卡片伪元素，因为伪元素容易盖住标题和交互按钮。建议在缩略图预览容器内渲染独立元素：

```tsx
{showRepairOverlay ? (
  <div
    data-testid="frame-repair-indicator"
    data-state={repairStopping ? 'stopping' : 'repairing'}
    className="storyboard-repair-overlay pointer-events-none absolute inset-0 z-10"
  >
    <span aria-hidden="true" className="storyboard-repair-scan" />
    <span className="storyboard-repair-label">
      {repairStopping ? '正在停止' : '正在优化'}
    </span>
  </div>
) : null}
```

具体 JSX 可按现有组件风格精简，但不要把扫描动画写成 React 状态或 JavaScript 循环。

### 5.3 UI chrome 保持清晰

编号、音频按钮、问题徽标必须处在修复层之上，例如统一使用 `z-20`。如果当前审计逻辑在修复开始时清空问题列表，不要为了视觉效果伪造或缓存一个过期问题数量；要求只是“仍存在的徽标不被模糊或遮挡”。

分镜标题仍在预览容器之外，不应改动。

选中边框属于卡片层，不应被修复蒙层覆盖。用户修复期间切换选中分镜时，选中态必须继续即时变化。

### 5.4 交互规则

修复期间：

- 允许点击卡片选中该分镜；
- 允许键盘 `Enter` / `Space` 选中；
- 允许横向滚动分镜条；
- 允许点击仍存在的质量问题徽标并打开质量面板；
- 音频按钮保持现有行为；
- 修复蒙层本身不响应点击，必须设置 `pointer-events: none`；
- 不在 `StoryboardStrip` 内新增“重新修复”或“停止”按钮；控制入口继续由质量面板负责。

质量面板当前已有批量任务忙碌与停止控制。本次只复用状态，不改变并发、禁用或停止规则。

## 6. CSS 实现规格

建议在 `src/app/globals.css` 现有 `/* Storyboard strip */` 区域附近新增样式，示意如下：

```css
.storyboard-thumbnail-content {
  transform: scale(1);
  filter: none;
  transition:
    filter 180ms var(--motion-ease-out),
    transform 180ms var(--motion-ease-out);
  transform-origin: center;
  will-change: auto;
}

.storyboard-thumbnail-content--repairing {
  filter: blur(2px) saturate(0.82) brightness(0.82);
  transform: scale(1.025);
}

.storyboard-repair-overlay {
  overflow: hidden;
  display: flex;
  align-items: center;
  justify-content: center;

.storyboard-repair-scan {

    rgb(var(--storyboard-repair-accent-rgb) / 0.05) 65%,
    transparent 100%
  );
  background-size: 220% 100%;

}

.storyboard-repair-label {
  position: relative;
  z-index: 1;
  border-radius: 999px;
  background: rgb(10 14 20 / 0.48);
  padding: 2px 6px;
  font-size: 9px;
  font-weight: 500;
  line-height: 1.25;
  letter-spacing: 0.02em;
  text-shadow: 0 1px 2px rgb(0 0 0 / 0.35);
  white-space: nowrap;
}

@keyframes storyboard-repair-scan {
  from { background-position: 160% 0; }
  to { background-position: -60% 0; }
}
```

这段代码是设计规格，不要求逐字符照抄。最终实现必须满足以下性能约束：

- 不要长期给所有缩略图设置 `will-change: filter`；仅活动状态需要时才可使用，或完全不使用。
- 不要使用 SVG `feTurbulence`、`backdrop-filter` 大半径模糊或鼠标位置监听。
- 不要为每帧更新 CSS 变量。
- 动画只改变 `background-position` 或独立扫描层的 `transform`，不要持续改变卡片布局尺寸。
- 多个并发修复分镜不能造成分镜条抖动、宽度变化或滚动位置跳动。

### 6.1 日间主题

日间主题下：

- 蒙层改为冷灰半透明；
- 扫描光带使用蓝色；
- 状态胶囊可以使用高透明深灰，确保白色小字有稳定对比度；
- 不要把整个缩略图漂白到无法识别。

### 6.2 减少动态效果

在现有 `@media (prefers-reduced-motion: reduce)` 中补充：

```css
.storyboard-repair-scan {
  animation: none;
  background-position: center;
}

.storyboard-thumbnail-content {
  transition-duration: 0ms;
}
```

减少动态效果时仍保留：

- `2px` 柔焦；
- 降饱和、降亮度；
- 中性蒙层；
- 一条静态、低透明度的中央光带；
- “正在优化”或“正在停止”文案。

也就是说，只移除运动，不移除状态表达。

## 7. 可访问性

1. 卡片原有 `aria-label="选择分镜 #N 标题"` 在修复期间应追加状态，例如“正在优化”，使聚焦卡片时能知道该镜状态。
2. 视觉扫描层本身标记 `aria-hidden="true"`，避免屏幕阅读器读取装饰元素。
3. 状态文字只需要被读一次，不要让每个动画循环触发 live region。
4. 如果使用 `role="status"`，状态节点只能随任务状态挂载或文案变化，不能随扫描动画重建。
5. 批量修复多个分镜时避免连续播报大量重复消息。可在分镜条容器增加一个屏幕阅读器可见的汇总 live region，例如“正在优化 3 个分镜”，各卡片通过扩展后的 `aria-label` 提供单镜状态。
6. 修复状态不能移除卡片的键盘焦点，也不能改变现有 `Enter` / `Space` 行为。
7. 文案与蒙层的视觉对比度要在深色和日间主题下人工检查；小字号不应只依赖扫描光带形成对比。

## 9. 自动化测试清单

至少新增以下覆盖：

### 9.1 请求提交后立即显示

仅设置：

```ts
qualityRepairRequests: { 'frame-1': 1 }
```

- 文案为“正在优化”；
- 画面共同包装层有 repairing class；
- 分镜标题没有该 class。

### 9.2 所有活动阶段显示

参数化测试 `auditing`、`sampling`、`optimizing`、`visual_repairing`、`terminal_verifying`、`sampling_recheck`、`saving` 和 `cancelling`。

断言对应分镜显示状态；`cancelling` 或活动停止标记显示“正在停止”。

### 9.3 终态不残留

参数化测试 `passed`、`saved`、`needs_review`、`unchanged`、`unavailable`、`cancelled` 和 `failed`，同时确保没有 `qualityRepairRequests`。

断言修复蒙层不存在、画面没有 repairing class。

### 9.4 多分镜并发

两个或以上分镜同时存在活动请求。

断言：

- 每个活动分镜都有独立 indicator；
- 未活动分镜没有 indicator；
- 数量与活动分镜数量一致。

### 9.5 首次生成优先

同一分镜同时具有：

```ts
generatingFrames: { 'frame-1': 'html' }
qualityRepairRequests: { 'frame-1': 1 }
```

断言：

- 保留现有 `frame-generation-indicator`；
- 不显示 `frame-repair-indicator`；
- 不出现两套状态文案。

### 9.6 交互不被拦截

断言：

- 点击修复中的卡片仍调用 `onFrameSelect(frameId)`；
- 键盘 `Enter` 或 `Space` 仍能选中；
- 仍存在问题徽标时，点击会调用 `onQualityOpen(frameId)`，且不会重复触发卡片点击；
- 蒙层具有 `pointer-events: none` 对应 class。

先设置活动请求并断言出现，再清空请求、设置终态并断言消失，防止完成后蒙层残留。

## 10. 浏览器视觉验收

自动化测试通过后，必须在真实浏览器中检查。建议准备至少 3 个分镜：横屏图片分镜、横屏 HTML 分镜、9:16 竖屏分镜。

### 深色主题

- 原画面仍能辨认，柔焦不超过“正在分析”的程度。
- 暗色蒙层不会把画面压成纯黑。
- 橙色扫描光带柔和，没有明显硬边或频闪。
- 选中描边、标题、编号和音频按钮清楚。

### 日间主题

- 冷灰蒙层不发白、不脏。
- 蓝色扫描光带和工作台主色协调。
- 白色状态文字在胶囊上清楚，不依赖图片背景。

### 尺寸与并发

- `128px` 横屏缩略图文案不拥挤。
- `72px` 竖屏卡片不裁切“正在优化”。
- 1、2、5 个分镜并发时动画流畅，分镜条不抖动。
- 横向滚动和点击选中正常。

### 生命周期

- 点击“重新修复”后立即显示。
- 采样、视觉调用、验收和保存切换阶段时效果不断闪退或重新挂载。
- 修复成功、未改善、不可用、失败或取消后都能正确退出。
- 停止过程中显示“正在停止”，结束后恢复普通缩略图。

### 减少动态效果

在操作系统或浏览器模拟 `prefers-reduced-motion: reduce`：

- 扫描光带不移动；
- 仍能通过柔焦、蒙层和文案识别状态；
- 没有 spinner 或其他循环运动残留。

## 11. 验收标准

以下条件全部满足才算完成：

1. 修复状态完全由现有 Store 驱动，没有新增模拟状态。
2. 请求提交后立即反馈，完整覆盖排队、采样、模型修复、验收、保存和停止阶段。
3. 只模糊缩略图画面，不模糊标题、编号、按钮、问题徽标或选中描边。

6. 修复层不拦截选中、键盘操作、横向滚动、音频和质量问题入口。
7. 首次生成和重新修复不会同时叠加两套状态层。
8. 多分镜并发时每张卡片状态独立，任务完成后无残留。
9. `prefers-reduced-motion` 下无移动扫描，但静态状态仍清楚。
10. 不引入新依赖，不新增 iframe，不改变修复、保存、撤销或导出业务逻辑。
11. 定向测试、完整测试、类型检查、构建和 `git diff --check` 的真实结果均已记录。
