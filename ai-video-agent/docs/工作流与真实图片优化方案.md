# 工作流与真实图片优化方案

> 实施状态（2026-07-25）：阶段 A 已完成；阶段 C 的验收等级、人工确认和导出拦截已完成，视觉模型自动验收保留为后续能力；阶段 B 已完成共享依赖产物、执行前依赖校验、依赖哈希和中断产物复用，分镜路由整体迁移到单一动态 `runAgentGraph` 仍作为后续结构性重构；阶段 D 的数据字段合并和运行指标继续保留为迁移任务。

## 1. 目标

在不改变现有用户审批节点、项目数据主体和本地离线导出方式的前提下，解决以下问题：

1. `SceneSpec.renderMode` 在生成、预览、编辑和导出中的含义不一致。
2. 真实图片当前只通过 Pexels 元数据验收，无法证明具体人物、产品或历史对象正确。
3. 大纲和分镜使用两套编排方式，AgentTask 依赖记录不等于实际执行依赖。
4. `required` 实际允许自动降级，字段名称与行为不一致。
5. 跨层测试没有覆盖编导决策到最终 MP4 的完整链路。

本方案保留内部 `VisualAnchor` 名称以兼容已保存数据和 API，但用户界面统一称为“主题风格”。它只表示主题 Token 已确认，不表示系统从首镜学习了完整构图。

## 2. 核心设计原则

- 一个镜头只能有一个最终渲染契约：`html`、`image` 或 `ui-scene`。
- 生成、完成状态、主预览、缩略图、编辑和导出必须读取同一契约。
- Agent 编排器负责依赖和状态，API 路由只负责鉴权、输入校验、SSE 和结果映射。
- 图片验收区分“文件有效”“元数据相关”“视觉语义确认”三个等级。
- 自动降级不能掩盖高保真素材缺失；必须留下可见且可处理的质量状态。
- 先修一致性，再引入新的视觉模型，避免在错误链路上增加成本。

## 3. 统一镜头渲染契约

### 3.1 新增规范化结果

在进入分镜生成前，将 `SceneSpec` 规范化为唯一的 `ResolvedSceneContract`：

```ts
type ResolvedSceneContract =
  | { mode: 'html'; requiresHtml: true; allowsEmbeddedAssets: true }
  | { mode: 'image'; requiresImage: true; allowsEmbeddedAssets: false }
  | { mode: 'ui-scene'; requiresUiDocument: true; allowsEmbeddedAssets: false };
```

规范化函数必须同时供生成接口、`isFrameSourceComplete`、预览和 Render Worker 使用，禁止各层自行推断。

### 3.2 三条明确分支

#### HTML

- TTS 与素材准备并行。
- 素材可作为 HTML 内的稳定图片槽位。
- 只在本模式调用 `visual-composer`。
- 完成条件：`htmlCode` 存在且通过 HTML/可见性检查，音频满足当前生成要求。

#### Image

- TTS 与图片准备并行。
- 不调用 HTML 合成器。
- `imagePath` 与 `realImage.localPath` 统一解析为一个 `resolvedImagePath`，逐步迁移到单一字段。
- 预览和导出共用 `fitMode`、裁剪位置和镜头运动参数。
- 完成条件：本地图片存在、签名和哈希正确，音频满足当前生成要求。

#### UI Scene

- TTS 与确定性 UI 文档校验并行。
- 不调用通用 HTML 合成器。
- 预览和导出都由同一个 `UISceneDocument` 渲染器生成。
- 完成条件：schema、archetype、动作和演示数据标记全部有效。

### 3.3 迁移兼容

- 旧 HTML 项目没有 `renderMode` 时继续解析为 `html`。
- 旧图片项目继续读取 `imagePath`。
- 已存在 `realImage` 但没有 `imagePath` 的 image 镜头，统一解析为 `realImage.localPath`。
- 不立即删除 `htmlCode` 或旧字段；先完成读取兼容，再通过后续迁移清理。

## 4. 真实图片分级验收

### 4.1 验收等级

```ts
type AssetVerificationLevel =
  | 'file-valid'
  | 'metadata-matched'
  | 'vision-confirmed'
  | 'human-confirmed';
```

- `file-valid`：MIME、文件头、大小、分辨率和哈希通过。
- `metadata-matched`：查询、Pexels alt、必需词和排除词通过。
- `vision-confirmed`：视觉模型检查主体、数量、场景和排除项。
- `human-confirmed`：用户在候选面板明确确认。

UI 不再把 `metadata-matched` 称为“可靠图片已验收”，而显示“元数据匹配”；只有后两级显示“内容已确认”。

### 4.2 按风险选择验收方式

| 素材类别 | 最低等级 | 缺失时行为 |
| --- | --- | --- |
| 普通环境、办公室、自然氛围 | metadata-matched | 可自动降级 HTML |
| 普通人物活动、通用设备 | vision-confirmed | 降级并显示提醒 |
| 指定人物、品牌产品、建筑身份 | vision-confirmed 或 human-confirmed | 进入待确认状态 |
| 历史现场、新闻事件、证据性画面 | human-confirmed，且来源可信 | 禁止用普通图库冒充 |

视觉检查必须使用具备图像理解能力的模型；DeepSeek 继续仅用于文本任务。

### 4.3 视觉检查输出

视觉模型只返回结构化判断，不负责重新设计画面：

```ts
interface AssetVisionReview {
  decision: 'pass' | 'uncertain' | 'reject';
  subjectMatched: boolean;
  requiredObjectsPresent: string[];
  missingObjects: string[];
  excludedObjectsPresent: string[];
  compositionUsable: boolean;
  confidence: number;
  reason: string;
}
```

`uncertain` 不自动冒充 `pass`。它可以保留为候选，但不能自动用于高风险镜头。

## 5. Agent 编排收敛

### 5.1 目标 DAG

```text
content-planner
  -> content-quality
  -> director
  -> scene-contract-resolver
      -> frame:N:tts -----------+
      -> frame:N:asset-plan     |
      -> frame:N:asset-prepare -+-> frame:N:renderer -> frame:N:validator -> frame:N:committer
```

其中 renderer 按契约映射为：

- `visual-composer`：仅 HTML；
- `image-resolver`：图片路径、裁剪和运动参数；
- `ui-scene-renderer`：确定性系统组件。

### 5.2 执行职责

- `runAgentGraph` 成为唯一依赖执行器。
- `runRecordedAgentTask` 只作为图执行器内部能力，业务路由不直接调用。
- 任务必须通过 `context.getArtifact()` 获取依赖结果，不能依赖外部闭包中的可变状态。
- SSE 进度由 graph hook 转换，避免业务代码同时维护 Agent 状态和前端阶段状态。
- 项目提交继续使用乐观锁，但由独立 committer task 完成。

### 5.3 恢复策略

- 每个 task 的 `inputHash` 必须包含依赖 artifact 的内容哈希和管线版本。
- 已完成 task 即使所属 run 被标记为 `interrupted`，只要 artifact 完整且输入哈希一致，也允许安全复用。
- 恢复时重新执行未完成、失败或输入变化的任务，不重复调用已持久化的 TTS、下载和 HTML 合成。
- 单镜失败继续隔离，不终止其他镜头。

## 6. 素材策略语义

把当前 `required` 拆为两个维度：

```ts
interface AssetRequirement {
  attempt: 'never' | 'optional' | 'required';
  failurePolicy: 'allow-native' | 'needs-review' | 'block';
}
```

- `required + allow-native`：必须尝试，失败可降级，适合普通实体语境。
- `required + needs-review`：生成可继续，但项目出现待确认质量项。
- `required + block`：禁止最终导出，适合用户明确要求的身份/证据画面。

旧数据迁移规则：

- `realImagePriority=never` → `never + allow-native`
- `preferred/optional` → `optional + allow-native`
- `required` → `required + needs-review`

## 7. 用户工作流调整

建议阶段固定为：

1. 生成并确认内容计划。
2. HTML 项目可生成首镜样片。
3. 用户点击“确认主题风格”，只确认颜色、字体、留白、标签和运动节奏 Token。
4. 生成其余镜头。
5. 高风险真实素材集中进入“素材待确认”。
6. 自动质量检查完成后预览。
7. 阻断项处理完毕后离线导出。

如果未来要真正从样片继承视觉语言，应新增独立的 `SampleStyleExtraction`，从首镜提取可复用 Token；在此之前不要恢复“定调”“锁定视觉方向”等措辞。

## 8. 实施顺序

### 阶段 A：一致性修复（优先级最高）

1. 引入 `resolveSceneContract`。
2. 修正 ImageFrame 对 `realImage.localPath` 的读取。
3. 让 `isFrameSourceComplete` 按镜头契约判断。
4. HTML 路由跳过 image/ui-scene 的 HTML 合成。
5. 统一预览和导出的图片运动、裁剪和 fitMode。
6. 修正仍指向浏览器录屏的导出提示。

验收：同一项目的缩略图、主预览、完成状态和 MP4 对每个镜头使用同一渲染模式与素材。

### 阶段 B：编排统一

1. 把分镜 worker 循环迁移为动态 Agent DAG。
2. 统一 hooks、进度、失败隔离和恢复。
3. 删除路由中的依赖元数据模拟和重复 save queue。

验收：AgentTask 依赖图能够真实解释执行顺序；中断后只重跑必要任务。

### 阶段 C：图片语义验收

1. 增加验收等级和视觉检查结果类型。
2. 先对 named-person、product、historical-scene 开启视觉检查。
3. 增加人工确认入口和阻断策略。
4. 调整候选面板措辞和筛选原因。

验收：指定人物或产品不会仅凭 alt 文字自动标记为内容已确认。

### 阶段 D：数据清理与观测

1. 合并重复的 `imagePath`、`realImage`、`imageAsset` 表达。
2. 为任务记录耗时、复用、模型调用次数、图片拒绝原因和降级率。
3. 根据真实数据调整并发数、超时和图片配额。

## 9. 测试矩阵

至少新增以下集成测试：

1. `renderMode=image + realImage`：预览、完成状态和导出读取同一路径。
2. `renderMode=ui-scene`：不调用 HTML 合成器。
3. `renderMode=html + realImages[]`：所有素材槽位均进入预览和导出缓存哈希。
4. 元数据通过但视觉检查 reject：不能自动应用高风险素材。
5. `required + needs-review`：生成继续但导出首次被拦截。
6. 分镜任务中断恢复：不重复 TTS 和已下载候选。
7. AgentTask dependencies 与真实调用顺序一致。
8. 主题风格确认：后续 prompt 获得 Token，但不声称复制首镜构图。

## 10. 完成标准

- 用户看到的镜头与导出 MP4 一致。
- 每个镜头只有一个最终渲染契约。
- 高风险真实图片具有视觉或人工确认记录。
- AgentTask 数据可以用于解释、恢复和审计，而不只是日志。
- “主题风格”在 UI、README、错误提示和测试中用词一致。
- 所有新增行为均有单元测试和至少一条跨层集成测试。
