# 智能配图检索失败交接文档

## 1. 问题摘要

“海上风电场紧急检修：从故障识别到安全执行”项目（`05164f14-17d1-492d-a40a-240378f51e8d`）的首镜应使用海上风机真实图片，但最终没有下载图片，也没有可供替换的候选图。

这不是 Pexels 没有素材，也不是英文查询词错误。根因是素材 Worker 将未拆分为 `subjects` 的默认素材请求错误识别为 `person`，从而用肖像搜索并强制肖像元数据筛选，误杀了正常的横版海上风机照片。

## 2. 已验证证据

### 2.1 项目实际请求

首镜的 `AssetRequest`：

```json
{
  "query": "offshore wind turbine at sea",
  "fallbackQueries": ["wind farm offshore turbine"],
  "requiredTerms": ["wind", "turbine"],
  "optionalTerms": ["offshore", "sea"],
  "excludedTerms": ["onshore", "solar"],
  "subjectType": "equipment",
  "purpose": "展示海上风机实物，强化真实感",
  "imageRequired": true
}
```

该镜最终持久化的降级记录为：

```text
Pexels -> HTML
原因：未找到足够匹配的真实素材
```

`realImage`、`realImages` 和 `imageSelection` 均为空。

### 2.2 同一 Key 的 Pexels 实测

以同一 Pexels API Key、`landscape` 方向查询 `offshore wind turbine at sea` 返回 7,596 条结果。前排候选包括：

- `31564458`：`Offshore wind turbines generating clean energy in the ocean breeze.`
- `11001079`：`A serene view of offshore wind turbines generating renewable energy under a blue sky...`
- `27197661`：`Offshore wind turbines generating sustainable energy over a calm ocean...`

这些图片均为可用横图，且 alt 同时包含 `wind` 和 `turbines/turbine`，符合本镜主题。结论：查询词可用，Pexels 素材充足。

## 3. 根因

当前 `src/lib/pexels/smart-images.ts` 在没有 `plan.subjects` 和 `plan.people` 时创建默认请求：

```ts
{
  name: args.plan.subject,
  query: args.plan.query,
  fallbackQuery: ...
}
```

随后用如下逻辑判断主体类型：

```ts
const requestKind = 'kind' in request ? request.kind : 'person';
const personRequest = requestKind === 'person';
```

默认请求没有 `kind`，因此被错误归类为 `person`。后续调用会：

1. 用 `portrait` 而非 `landscape` 方向查询 Pexels；
2. 开启 `requirePortrait: true`；
3. 开启 `requireSubjectMatch: true`；
4. 将海上风机等非肖像照片全部拒绝。

这使得一个 `subjectType: equipment` 的请求走进了人物筛选路径。

## 4. 相关但独立的问题

### 4.1 失败候选没有持久化

当前只有自动选中并下载成功后，才会向 `FrameSource.imageSelection` 写入候选。所有候选被拒绝时，查询词、候选 alt、拒绝理由和评分没有保存，编辑器也直接隐藏候选区域。

结果是用户只能看到占位图或原生图解，无法区分：

- 未计划搜图；
- Pexels 服务不可用；
- 有候选但被规则拒绝；
- 下载失败；
- HTML 未引用已下载图片。

### 4.2 “标准文件封面”不应使用 Pexels

同项目第 9 镜查询“海上风电标准文件封面”。即使修复主体类型，Pexels 也不应被当作具体国家标准封面的可信来源；该镜应使用原生引用/文档图解，或使用用户提供、可验证的原始文件封面。

## 5. 修复方案

### 5.1 按 `AssetRequest.subjectType` 决定检索模式

默认请求必须带上规划器的主体类型，不能默认人物：

```ts
const personRequest = args.plan.assetRequest?.subjectType === 'person';
```

规则：

| `subjectType` | Pexels 方向 | 肖像校验 |
| --- | --- | --- |
| `person` | `portrait` | 必须 |
| `equipment` | `landscape` | 禁止要求 |
| `place` | `landscape` | 禁止要求 |
| `environment` | `landscape` | 禁止要求 |

对显式 `subjects[]`，仍优先使用每个 subject 的 `kind`；`kind: person` 才启用肖像模式。

### 5.2 完整持久化候选决策

无论最终是否下载，都应保存：

- `AssetRequest` 与每次实际查询词；
- 前 3 个候选的 Pexels ID、缩略图 URL、alt、画幅、分数；
- 命中的必需词、命中的禁词、拒绝原因；
- 自动选择、下载、HTML 引用和最终应用的独立状态；
- 最终降级或阻断原因。

编辑器在没有候选时也必须显示“配图诊断”空状态，不能直接隐藏整个区域。

### 5.3 Director 契约冲突归一化

若 Director 输出 `assetStrategy: real-image` 却没有有效 `assetRequest`，或 `imagePurpose` 明确表示“无需真实图片”，归一化器应：

1. 记录 `ASSET_REQUEST_MISSING` 或 `ASSET_STRATEGY_CONFLICT`；
2. 改为原生视觉策略；
3. 不生成“真实图片占位”。

## 6. 验收与回归测试

### 海上风机 fixture

输入：

```json
{
  "subjectType": "equipment",
  "query": "offshore wind turbine at sea",
  "requiredTerms": ["wind", "turbine"],
  "excludedTerms": ["onshore", "solar"]
}
```

期望：

- 调用 Pexels 时使用 `landscape`；
- 不设置 `requirePortrait`；
- alt 为 `Offshore wind turbines generating clean energy...` 的候选可以通过；
- 至少保留 1 个自动选择和最多 3 个可替换候选；
- 失败时也能在 UI 看到候选与拒绝理由。

### 人像 fixture

输入 `subjectType: person` 时，必须使用 `portrait` 并拒绝无人物证据的建筑、设备和风景图。

### 文档封面 fixture

请求包含 `standard document cover`、`imageRequired: true` 且 Pexels 无可验证封面时，应返回“缺少可靠素材”，不得用办公室、会议或通用文件夹照片填充。

## 7. 涉及文件

- `src/lib/pexels/smart-images.ts`：默认请求的主体类型与候选决策持久化；
- `src/lib/pexels/scoring.ts`：硬过滤与拒绝理由；
- `src/lib/ai/director.ts`：`AssetRequest` 输出和冲突归一化；
- `src/lib/ai/real-image-planner.ts`：是否搜索的确定性决策；
- `src/components/studio/candidate-images-panel.tsx`：候选图与空状态诊断；
- `tests/smart-images.test.ts`、`tests/pexels.test.ts`：检索方向、候选筛选和回归 fixture。

## 8. 实施结果（2026-07-24）

本交接文档中的核心故障已修复，并补上了从检索到编辑器切换的完整可靠性链路：

- 默认请求已按 `AssetRequest.subjectType` 选择检索方向，`equipment/place/environment` 不再进入人物肖像筛选；
- 主查询和回退查询的合格候选会合并去重、统一评分，每个素材槽最多保留 3 张；
- 必需词改为“全部满足”，分辨率、下载地址、画幅、排除词、人物证据和主题证据均有明确拒绝码；
- 合格候选在展示给用户前全部下载到本地，校验 JPEG/PNG/WebP 文件签名并记录 SHA-256；
- `imageSelection` 会保存实际查询、合格候选、被拒候选、缺失词、最终状态和失败原因，失败时编辑器不再隐藏；
- HTML 图片会绑定稳定 `data-asset-slot`，一键切换只修改目标图片的 `src`/`alt`，并验证所有真实图片仍在视觉区中；
- 切换接口只读取已校验的本地候选，不再在用户点击时访问远程图片；同时使用 HTML 版本和候选版本防止并发覆盖；
- Pexels 网络异常和 5xx 会短暂重试一次，401、429 等确定性错误不做盲目重试；
- 已增加海上风机横图回归、人物检索、完整必需词、失败诊断、稳定素材槽和候选面板一键切换测试。
