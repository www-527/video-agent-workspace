# 三采样点视觉修复优化计划

## 目标

将当前 HTML 分镜的本地穷举式自动修复，改为“视觉证据驱动的一次修复”：保留 35%、70%、100% 三个采样点作为修复输入，由视觉修复 Agent 结合截图、当前 HTML、DOM 质量问题与当前分镜大纲生成一份修复后的完整 HTML。

默认只在 100% 终态进行快速验收；只有动画或时序风险明确存在时，才回退到三个采样点复检。

## 背景与问题

现有本地修复会对每个镜头枚举多个 CSS 修改候选，并在三个动画进度点重复审计。其最坏规模为：

```text
初始审计：3 个采样点
最多 4 轮修复 × 每轮最多 24 个候选 × 每候选 3 个采样点
= 单镜最多 291 次 iframe 审计
```

全片按镜头串行运行时，修复时间会随分镜数量快速累积。局部几何规则也无法可靠理解构图、层级与动画意图。

## 目标流程

```text
当前 HTML
  -> 采样 35% / 70% / 100% 三张截图，并得到对应 DOM 审计问题
  -> 一次视觉修复 Agent 调用
     输入：三张截图、当前 HTML、当前镜大纲、问题清单、画布与安全区约束
     输出：一份完整修复后的 HTML
  -> 修复后默认审计 100% 终态
  -> 若满足动画风险条件，补做 35% / 70% / 100% 三点复检
  -> 仅在质量改善且没有新增严重问题时保存
```

## 输入与输出契约

### Agent 输入

- 采样截图：35%、70%、100%，按时间点明确标注；不持久化 data URL。
- 当前 HTML：完整文档，供 Agent 保留结构、文本、稳定 `data-editor-id` 与本地资源。
- 当前分镜大纲：仅包含 `title`、`narration`、`htmlPrompt`、`sceneSpec`、时长和必要的短上下文；不发送整片大纲。
- 审计问题：问题代码、严重程度、元素 ID、相关元素 ID、几何详情与建议修复。
- 画布约束：尺寸、内容安全区、字幕安全区、禁止外部资源和禁止伪装修复的规则。

### Agent 输出

- 仅输出一份独立的完整 HTML 文档。
- 不得改写屏幕文字、旁白事实、时长语义、跨镜内容、稳定元素 ID 或本地资源路径。
- 不得引入外部网络资源、循环动画、随机行为或交互依赖。

## 修复后验收策略

### 默认：只检查 100% 终态

对修复后的 HTML 在 100% 采样点进行 DOM 与视觉审计。该路径覆盖静态问题：

- 字号和对比度；
- 最终态越界、裁切、字幕安全区；
- 终态的文字遮挡和语义重叠；
- HTML 安全清洗、可见文本、稳定 ID 和本地资源完整性。

### 升级：三个采样点复检

满足任一条件时，修复后重新检查 35%、70%、100%：

- 原始问题只在 35% 或 70% 采样点出现；
- 原始问题是过程中的遮挡、越界或字幕区侵入；
- 修复结果修改了 `@keyframes`、`animation`、`transition`、`transform` 或时序相关元素；
- 视觉 Agent 明确变更了入场、出场或过程位置。

只有所有必需采样点没有新增严重问题、且质量向量优于原版时，候选才可保存。

## 实现计划

### 1. 建立截图采样 owner

新增 `src/lib/quality/visual-self-repair.ts`，集中负责：

- 在受控渲染环境生成三个时间点截图；
- 将截图和审计问题按同一采样 nonce 关联；
- 处理超时、取消、无效图片与截图大小限制；
- 返回仅用于当前请求的临时图像数据与可持久化的安全摘要。

不要从 sandbox iframe 直接用 canvas 截图。应复用受控 HTML 渲染能力，以保证截图稳定、可访问且不会突破 sandbox 隔离。

### 2. 扩展多模态 HTML 调用

扩展 `callAIHtml` 与 GPT / Codex Responses 传输层，使单次 HTML 修复调用可以携带三张输入图片。

- 保留现有 AI Key 上下文、取消、脱敏 trace 与失败语义；
- 每个修复任务只允许一次模型请求；
- 图像数据不能进入质量报告、localStorage、错误响应或普通控制台日志；
- 不支持视觉输入的模型配置返回 `vision_unavailable`，不降级为另一套隐式模型或重试链路。

### 3. 改造修复 Agent 与接口

修改 `frame-quality-repair.ts` 和 `/frame-quality/repair`：

- 使用截图、HTML、当前镜大纲和审计问题构造视觉修复提示；
- 保留现有 HTML 清洗、完整 HTML 提取、文本/ID/资源保护；
- 一次 Agent 输出后，将候选交给新的终态验收策略；
- 返回 `accepted`、`unchanged`、`unavailable`、`cancelled` 或 `failed`，并携带可显示的安全摘要。

### 4. 调度与保存边界

修改 `PreviewPanel`：

- 自动模式只生成轻量质量报告，不对整片后台执行深度修复；
- 用户点击“重新修复”时，只处理当前分镜；
- 保持现有串行、AbortController、停止任务和唯一保存入口；
- 仅 `accepted` 结果调用现有 `frame-tunes/apply` 保存；其他结果保留原 HTML。

旧的多轮本地候选穷举不再作为 AI 修复的前置步骤。可以保留单次、廉价的确定性修复作为可选快速路径，但不得再形成多轮候选搜索。

### 5. UI 与控制台反馈

质量面板显示：采样中、视觉修复中、终态验收中、三点复检中、已保存、未改善、模型不可用或已取消。

浏览器控制台继续使用 `[画面修复][frameId]` 前缀，只记录阶段、采样点、耗时、问题数量、验收决定和错误摘要；绝不记录截图、HTML、提示词或密钥。

## 测试与验收

新增或更新以下覆盖：

1. 三截图按 35% / 70% / 100% 生成，并能正确取消、超时和拒绝无效图片。
2. 修复调用只发起一次多模态 AI 请求，且图像顺序与采样点一致。
3. Agent 输入包含当前镜大纲和问题清单，不包含完整全片大纲。
4. 静态问题走“100% 终态验收”；动画风险命中后走“三点复检”。
5. 文本、稳定 ID、本地资源、HTML 安全规则和导出路径保持不退化。
6. `unchanged`、`failed`、`unavailable`、`cancelled` 均不保存候选，也不阻断导出。
7. 手动修复仅处理当前镜；自动模式不会串行深度修复整片。

## 风险与回滚

- 视觉模型不可用、截图失败、超时或候选未改善：不保存候选，保留原画面，不阻断导出。
- 视觉模型改写内容：继续由 HTML 清洗、可见文本、稳定 ID、本地资源和复审门禁拒绝。
- 性能与成本：每镜每次手动修复最多一次视觉调用；截图只保留在请求内存中。
- 回滚：关闭视觉修复入口即可恢复为仅质量检查；不涉及数据库迁移或持久化截图。
