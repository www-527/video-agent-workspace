# 画面自测与自动优化方案

## 1. 目标

在每个 HTML 分镜生成完成后，自动执行“浏览器渲染采样 → DOM/CSS 规则检测 → 生成修复候选 → 实际渲染评分 → 保存最优结果 → 复检”的闭环。只有通过质量门的分镜才标记为完成；未通过的分镜不得静默进入导出。

本方案完全不依赖视觉模型、OCR 或图片理解 API。检测依据全部来自浏览器可重复计算的数据：DOM 结构、元素几何、文字行框、CSS 层叠、命中测试、字体指标、颜色和资源加载状态。因此它可以直接建立在当前 HTML 分镜、隐藏 iframe 和编辑补丁能力之上。

本系统优先解决：

1. 文字或重要视觉元素被其他元素遮挡。
2. 文字出框、被裁切、进入字幕安全区。
3. 标题、正文、标签字号过小，行高或行宽不合理。
4. 元素间距不足、贴边、跨越文字区与视觉区、画面明显拥挤。
5. 低对比度文字、透明度过低、空白画面或关键元素不可见。
6. 自动修复造成的新问题，并能回滚到修复前版本。

本系统不承诺判断图片内容是否“好看”、人物是否裁脸、素材是否符合语义。这类需要理解图片内容的问题不在当前自测范围内。系统保证的是可被程序客观验证的排版与渲染质量。

“最终质量保证”采用硬质量门实现：程序不能证明画面合格时，不把它标记为通过，也不允许直接导出。自动修复无法解决时，进入带检测报告的定向重生成，而不是继续使用问题画面。

## 2. 当前基础与主要缺口

项目已经具备以下基础：

- `iframe-utils.ts` 会在动画终态检测 `out_of_bounds`、`clipped`、`subtitle_safe_area`。
- `preview-panel.tsx` 会在导出前用隐藏 iframe 逐帧预检，并阻止问题分镜导出。
- 每个可编辑元素有稳定的 `data-editor-id`，可通过 `applyEditCommand()` 注入持久 CSS 补丁。
- 已有分镜微调保存接口，可以保存修复后的 HTML。

当前缺口：审计只返回问题标签，缺少元素坐标、遮挡关系、严重度和可执行修复建议；检测只看终态；没有自动修复循环；没有质量评分和“修复必须优于原版”的回滚条件。

## 3. 总体闭环

```text
生成 HTML
  ↓
等待字体、图片和动画采样点就绪
  ↓
采集布局快照（元素、文字行框、层级、可见性）
  ↓
规则检测 + 画面评分
  ↓
是否通过质量门？ ── 是 → 保存审计报告 → 标记完成
  │
  否
  ↓
按优先级生成有限个修复候选
  ↓
隐藏 iframe 实际渲染每个候选并重新评分
  ↓
选择“零新增严重问题且分数提升最大”的候选
  ↓
保存补丁并进入下一轮（最多 3 轮）
  ↓
仍有严重问题？ ── 否 → 标记完成
  │
  是
  ↓
携带结构化规则报告定向重生成 1 次
  ↓
仍不通过 → 标记 needs_review，阻止导出
```

## 4. 检测模型

### 4.1 多时点采样

不能只检查动画结束后的单帧。每个分镜至少检查：

- `t=0`：初始状态，排除首帧闪烁或错误元素残留。
- `t=35%`：动画进行中，发现穿越文字、临时遮挡。
- `t=70%`：主要信息通常已出现。
- `t=100%`：最终静态布局。

审计模式应冻结 CSS Animation、Transition、Web Animation API 到指定时间点，不修改持久 HTML。字体使用 `document.fonts.ready`，图片等待 `decode()`；任何资源超时都作为独立问题上报。

### 4.2 元素快照

对每个 `[data-editor-id]` 采集：

- `DOMRect`、`Range.getClientRects()` 文字行框。
- `display`、`visibility`、`opacity`、`z-index`、`overflow`。
- `font-size`、`line-height`、前景色、实际背景色。
- 元素类型：`title | body | label | image | visual | decoration | composite`。
- 所属 `text-zone`、`visual-zone`、`composite` 和父级裁切容器。
- 是否为关键元素。标题、正文、带语义标签的图片/组合体默认关键；`data-role="decoration"` 默认非关键。

建议生成阶段补充 `data-qa-role` 与 `data-qa-priority="critical|normal|decorative"`。旧分镜可根据标签、DOM 标签和 `data-role` 推断。

### 4.3 检测规则

| 问题 | 检测方法 | 默认严重度 |
|---|---|---|
| 画布出界 | 元素 rect 超过 1280×720 | critical |
| 父容器裁切 | rect/文字行框超过任一非 visible overflow 祖先 | critical |
| 字幕区侵入 | 关键内容 bottom > 600 | critical |
| 文字遮挡 | 对每个文字行框做网格采样，`elementsFromPoint()` 顶层元素不是自身/后代，且不属于同一 composite | critical |
| 视觉遮挡文字 | 遮挡文字有效面积超过 3%，或连续遮挡宽度超过一个字符高度 | critical |
| 无关元素重叠 | 两个语义元素交集面积 / 较小元素面积超过 8%，排除同一 composite | major |
| 字号过小 | 标题 < 48px；正文 < 24px；标签 < 18px | major/critical |
| 行高异常 | line-height < 1.15 或 > 1.8；行框相互压叠 | major |
| 行宽过长 | 中文正文单行估算超过 28 字，或英文超过约 65 字符 | minor |
| 贴边 | 关键元素距画布边缘 < 48px，普通内容 < 32px | major |
| 区域串位 | text-zone 与 visual-zone 越过保护间隔，或关键元素进入错误区域 | major |
| 对比度不足 | 按 WCAG 相对亮度计算；正文 < 4.5:1，大字 < 3:1 | major |
| 不可见 | 关键元素 opacity < .85、面积为 0、完全被覆盖 | critical |
| 空画面 | 可见非装饰内容面积过低，或关键元素数为 0 | critical |
| 资源异常 | 图片加载失败、字体超时、审计超时 | critical |

#### 遮挡检测的降误报规则

仅用矩形相交会产生大量误报，因此使用“几何粗筛 + DOM 命中复核”：

1. 先用矩形相交筛出候选元素对。
2. 文字使用每个 `Range` 行框，而不是整个文字容器。
3. 在交集区域按 4～8px 或自适应网格采样 `elementsFromPoint()`；这是浏览器命中测试，不需要截图或视觉模型。
4. 同一 `data-role="composite"` 内的非文字部件允许重叠。
5. decoration 位于文字下方不算遮挡；位于文字上方且实际覆盖字形区域才算。
6. 对 transform、border-radius、clip-path 元素以命中采样结果为准。

## 5. 质量评分与质量门

每个采样时点满分 100，分镜总分取所有时点最低分，避免终态合格但中途穿帮。

建议扣分：

- critical：每项 -35；存在任何 critical 即不通过。
- major：每项 -12；超过 1 项不通过。
- minor：每项 -3。
- 同一根因产生的重复问题合并，避免一个裁切元素被重复扣分。

通过条件：

- 无 critical。
- major ≤ 1 且总分 ≥ 90。
- 所有文字无遮挡、无裁切、字号达到下限。
- 修复后分数必须高于修复前，且不得新增 critical。

## 6. 自动修复引擎

### 6.1 原则

- 规则引擎决定“改什么”，浏览器复检决定“是否接受”；生成模型不直接覆盖原 HTML。
- 每次只处理一个根因或一组强关联元素，降低连锁副作用。
- 优先移动和释放空间，其次缩放视觉元素；绝不通过把正文缩到 24px 以下来消除溢出。
- 不自动改标题、正文和事实内容，不删除语义元素。
- 每轮保存 before/after HTML、命令、评分和问题差异，可完整回滚。

### 6.2 修复优先级

1. **出界、裁切、字幕区**：将元素沿最短方向移回合法矩形；必要时最多缩小视觉元素 5%～15%。
2. **文字被遮挡**：优先移动遮挡方；若遮挡方是 decoration，则降层级或移动/隐藏 decoration；关键视觉与文字冲突时，分别尝试向各自区域中心移动。
3. **无关语义元素互相遮挡**：沿最小分离向量移动，保留至少 24px 间距。
4. **字号过小**：提升到角色下限；若因此溢出，扩大文字容器、减少非语义留白、移动相邻视觉元素；不得再次缩小字号抵消。
5. **对比度不足**：从主题 token 中选择前景色或增加半透明底板；不任意引入新颜色。
6. **拥挤或贴边**：以 8px 网格向安全区域微移，最大单轮位移 64px。
7. **无法安全局修**：进入定向重生成，不连续堆叠大量 CSS 补丁。

### 6.3 问题与确定性修复动作映射

| 问题 | 第一选择 | 第二选择 | 禁止动作 |
|---|---|---|---|
| `out_of_bounds` | 按越界量反向移动并加 8px 余量 | 视觉元素等比缩小至最多 85% | 缩小文字 |
| `clipped` | 移回最近的非裁切区域 | 扩大可编辑容器或缩小视觉元素 | 全局取消 `overflow:hidden` |
| `subtitle_safe_area` | 上移到 `bottom ≤ 592` | 缩小视觉元素并上移 | 移动字幕层 |
| `text_occluded` | 沿最小分离向量移动遮挡方 | decoration 降层或隐藏 | 降低文字层级 |
| `semantic_overlap` | 移动优先级较低者并留 24px | 双方各移动一半距离 | 随机改 z-index |
| `font_too_small` | 提升到角色最小字号 | 扩大文字框并挪开视觉元素 | 再缩回阈值以下 |
| `low_contrast` | 使用主题前景 token | 增加主题表面色底板 | 生成主题外随机颜色 |
| `edge_spacing` | 向安全区移动 | 小幅缩小视觉元素 | 改动画时长掩盖问题 |
| `empty_frame` | 检查关键元素 opacity/display/资源 | 定向重生成 | 添加无关装饰填空 |

### 6.4 候选搜索，而非单次猜测

针对一个问题生成 6～20 个有限候选，例如遮挡问题可尝试：

- `x ± 16/32/48px`
- `y ± 16/32/48px`
- 视觉元素 `scale 0.95/0.90/0.85`
- decoration `z-index` 下调或隐藏
- 组合动作：移动 32px + 缩小 5%

每个候选都通过 `applyEditCommand()` 或统一的 `AutoFixPatch` 生成临时 HTML，在隐藏 iframe 中按四个时点重新审计。选择目标函数最优者：

```text
candidateScore = qualityScore
               - 新增问题惩罚
               - 位移距离 × 0.03
               - 缩放变化 × 10
               - 修改元素数量 × 2
```

只有满足以下条件才落盘：

- 不新增 critical。
- 原问题消失或严重度下降。
- 总分至少提升 5 分，或直接达到质量门。
- 视觉关键元素缩放不得低于原始尺寸的 85%。

否则丢弃候选并保持原 HTML。

### 6.5 防止循环和越修越坏

- 单分镜最多 3 轮局部修复。
- 同一元素同一属性最多修改 2 次。
- 保存 `issueFingerprint + patchFingerprint`，禁止重复尝试。
- 连续两轮提升小于 3 分立即停止。
- 自动修复始终从“当前最佳 HTML”分支生成，不在失败候选上继续叠加。
- 定向重生成最多 1 次；仍不通过则 `needs_review`。

## 7. 定向重生成

局部补丁解决不了结构性拥挤时，把规则引擎产生的结构化报告附加到现有 `generateFrameHtmlWithRetry()`。这里仍使用程序当前已有的 HTML 生成模型，不新增视觉模型；模型只根据文本报告重排 HTML：

```text
上一版未通过画面质量门：
- title 被 monitor 遮挡 18%，发生在 t=70%、t=100%
- body 字号 20px，要求至少 24px
- monitor 进入字幕区 42px

必须保留：标题、正文、主要视觉主题、主题 token、真实图片。
必须改变：重新分配 text-zone / visual-zone 空间，不得通过缩小文字解决。
```

重生成后必须重新走完整审计，不能因为调用过 AI 就视为修复成功。

如果项目希望完全避免第二次生成调用，也可以关闭定向重生成。此时三轮规则修复后仍不合格的分镜直接进入 `needs_review`，并阻止导出。

## 8. 自测执行状态机

为避免“HTML 已保存但审计状态仍是旧的”，生成与自测必须使用明确状态机：

```text
rendered
  → auditing
  → passed
  → optimizing → auditing（最多 3 次）
  → regenerating → auditing（最多 1 次，可关闭）
  → needs_review
```

规则：

- `frame_done` 只代表 `passed`，不再代表 HTML 刚生成完成。
- HTML 每次变化都重新计算 `htmlHash`，旧报告立即失效。
- 只有 `report.htmlHash === currentHtmlHash`、`auditVersion` 相同且状态为 `passed` 才能导出。
- 浏览器关闭、超时或审计无返回均按 `audit_failed` 处理，不得默认通过。
- 自动修复保存 HTML 和质量报告必须由同一个项目更新完成，避免中间状态。

## 9. 数据结构建议

```ts
type QualityIssueCode =
  | 'clipped' | 'out_of_bounds' | 'subtitle_safe_area'
  | 'text_occluded' | 'semantic_overlap' | 'font_too_small'
  | 'line_height' | 'edge_spacing' | 'zone_intrusion'
  | 'low_contrast' | 'invisible' | 'empty_frame'
  | 'asset_failed' | 'audit_timeout';

interface QualityIssue {
  id: string;
  code: QualityIssueCode;
  severity: 'critical' | 'major' | 'minor';
  frameId: string;
  sampleTime: number;
  elementId: string;
  relatedElementId?: string;
  rect: { x: number; y: number; width: number; height: number };
  overlapRatio?: number;
  measured?: number;
  expected?: number;
  detail: string;
  suggestedActions: Array<'move' | 'resize' | 'restack' | 'recolor' | 'hide_decoration' | 'regenerate'>;
}

interface FrameQualityReport {
  frameId: string;
  status: 'pending' | 'optimizing' | 'passed' | 'needs_review';
  scoreBefore: number;
  scoreAfter: number;
  iterations: number;
  issues: QualityIssue[];
  appliedFixes: AutoFixPatch[];
  auditedAt: number;
  auditVersion: string;
  htmlHash: string;
  sampledAt: number[];
  durationMs: number;
}

interface AutoFixPatch {
  id: string;
  elementId: string;
  changes: Record<string, string | number>;
  reasonIssueIds: string[];
  beforeScore: number;
  afterScore: number;
}
```

报告必须保存在项目数据中，而不只放在 Zustand 内存 store；否则刷新页面后无法证明分镜是否通过质量门。

- `src/app/api/projects/[id]/quality/route.ts`：持久化报告和修复后 HTML。

修改现有位置：

- `iframe-utils.ts`：将当前 `auditLayout()` 升级为可传采样时间、返回完整快照的 `auditFrameQuality()`。
- `types/index.ts`：扩展 `LayoutIssue`，过渡期保留旧字段兼容 UI。

- `preview-canvas.tsx`：显示分数、问题元素高亮、自动修复前后差异。
- `preview-panel.tsx`：导出时读取持久化报告；审计版本过旧或 HTML hash 改变时强制重审。
- `editor-command.ts`：增加 `source: 'auto'`，并支持带审计元数据的批量原子补丁。

### 当前技术栈下的执行边界

当前版本直接复用隐藏 iframe，在浏览器端完成检测和候选渲染，不要求增加视觉模型或截图服务。生成接口返回 `frame_rendered` 后，前端 `quality-runner` 自动接管；用户无需点击预览。

需要明确一个运行限制：如果用户在自测完成前关闭页面，纯浏览器自测会中断。第一版应把状态保留为 `rendered/auditing`，用户再次打开项目时自动续跑，不能错误标记完成。以后若需要真正的离线无人值守能力，可以部署普通无头 Chromium worker；它仍运行相同 DOM 规则，不属于视觉模型，也不改变检测逻辑。

### 性能控制

- 同时最多审计 2 个分镜，避免大量 iframe 抢占内存。
- 单个采样点超时 1.5 秒，单轮审计超时 4 秒。
- 先跑便宜的几何/字号规则；无问题时跳过元素对遮挡复核。
- 遮挡粗筛使用空间网格，避免对 80 个元素做完整的密集两两扫描。
- 候选分两批：先试 6 个低成本位移候选，无改善再试缩放/层级组合。
- 通过的 HTML hash 缓存报告，重复预览不重新审计。

## 11. 用户界面

生成进度增加一个“画面自检”阶段：

```text
第 4 镜：生成完成 → 自检中 → 发现 2 项 → 自动优化第 1/3 轮 → 已通过（96 分）
```

预览右上角显示：

- 绿色：`已自检 96分`。
- 黄色：`已优化 91分 · 1项轻微问题`。
- 红色：`未通过 · 禁止导出`。

点击报告可查看问题元素、修复动作、前后分数，并提供“撤销自动优化”和“重新自检”。自动修复不弹确认框；只有无法通过时才要求人工处理。

## 12. 分阶段实施

### Phase 1：可靠检测与硬质量门

- 扩展审计数据结构。
- 完成文字遮挡、语义重叠、字号、对比度、贴边检测。
- 增加四时点审计和问题元素高亮。
- 审计报告持久化，HTML hash 或审计版本变化后自动失效。
- 导出只接受有效的 `passed` 报告。

验收：构造的出框、裁切、字幕侵入、文字遮挡、20px 正文、低对比度案例均能稳定检出；同一 composite 的合法组合不误报。

### Phase 2：确定性自动微调

- 实现候选生成、隐藏 iframe 并行试渲染、评分和回滚。
- 支持移动、缩放、字号提升、装饰降层/隐藏、主题色纠正。
- 在生成完成后自动运行，最多 3 轮。

验收：标准问题集至少 85% 自动修复通过；0 个案例出现修复后新增 critical 并被保存；失败候选 100% 回滚。

### Phase 3：定向重生成与稳定性

- 结构性问题携带报告定向重生成一次。
- 实现页面关闭后的任务续跑、超时恢复和审计报告版本失效。
- 保存审计报告、HTML hash 和耗时指标，不要求保存截图。

验收：批量生成时无需逐帧打开预览即可完成自测；中途关闭页面不会误报通过；所有导出分镜均有同版本有效审计报告。

### Phase 4：纯规则补强（可选）

- 使用 DOM 可见面积统计识别空画面和异常隐藏。
- 检查 animation/transition 的实际时间线是否存在、是否运行、是否在镜头时长内完成。
- 检查图片 `naturalWidth/naturalHeight`、加载状态、CSS `object-fit` 和容器裁切比例。
- 检查重复 ID、无效选择器、异常高 z-index 和过多编辑补丁。
- 不引入视觉模型；图片语义和审美判断继续作为人工复核范围。

## 13. 测试与上线指标

建立至少 100 个固定质量样本：50 个单一问题、30 个组合问题、20 个合法重叠/特殊设计反例。每次修改审计规则都跑回归。

核心指标：

- critical 检出率 ≥ 98%。
- 合法 composite 遮挡误报率 ≤ 2%。
- 自动修复成功率 ≥ 85%。
- 修复后新增严重问题保存率 = 0。
- 单分镜浏览器端自检 P95 ≤ 2.5 秒；含候选优化 P95 ≤ 8 秒。
- 导出的视频中，出框、裁切、字幕遮挡和小字号问题为 0。

测试不能只断言注入脚本包含某段字符串。至少增加三层测试：

1. 评分与修复候选的纯函数单元测试。
2. 用真实 iframe 构造遮挡、裁切、合法 composite 等固定页面的集成测试。
3. 从生成到自动优化再到导出门的端到端测试，包括审计超时和页面恢复。

## 14. 明确边界

本方案能够程序化保证：出框、裁切、字幕区侵入、可检测的文字遮挡、字号下限、间距、对比度、资源加载和关键元素可见性。

本方案不能自动判断：图片主题是否准确、人物表情是否合适、构图是否具有高级审美、图片内部是否包含不可读文字。界面和质量报告必须明确这一边界，避免把“规则自测通过”表述成对全部审美质量的绝对保证。

## 15. 推荐落地顺序

先实现 Phase 1 的可靠检测和持久化质量门，再实现 Phase 2 的自动修复。现有 DOM、iframe、`data-editor-id` 和 `applyEditCommand()` 已足够完成这两阶段，不需要安装或接入任何视觉模型。
