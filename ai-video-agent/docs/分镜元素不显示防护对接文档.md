# 分镜元素不显示防护对接文档

## 1. 文档目的

本文用于对接“HTML 分镜元素存在但画面不显示”的修复工作，覆盖：

- HTML 生成结果的保存前校验。
- iframe 预览中的运行态可见性检查。
- 质量评分与质量面板展示。
- MP4 导出前的同源检查。
- 回归测试与已有项目排查。

本次问题不是自动优化新增。自动优化的责任边界是：当前质量检查没有识别出最终仍为透明状态的核心元素，因而错误地将画面判定为通过。

## 2. 已确认问题

项目：

```text
AI Native如何真正落地：从管理系统到AI COO
projectId: 235d5083-4bcf-491f-a6c2-f79c3e907d49
```

目标分镜：

```text
frameId: frame-29
index: 29
title: Business Thinking Engine：四层系统
```

四个同心圆元素均存在于 DOM，但运行后保持：

```text
class: circle-layer layer-data
display: flex
visibility: visible
opacity: 0
transform: scale(0.9)
```

标题正常显示。直接原因是动画脚本注册 `load` 监听后立即将同一个监听移除：

```js
if (document.readyState === 'complete') {
  startAnimation();
} else {
  window.addEventListener('load', startAnimation);
}

window.removeEventListener('load', startAnimation);
```

在 iframe `srcdoc` 中执行脚本时，文档通常仍处于 `loading`，所以 `startAnimation()` 没有执行，依赖 `.active` 的元素永久保持透明。

## 3. 修复目标

1. 修复第 29 镜，让四层元素按顺序显示。
2. 同类动画生命周期错误不能再次作为有效 HTML 保存。
3. 核心视觉元素在最终检查点仍全部透明时，质量检查必须返回严重问题。
4. 质量分存在严重不可见问题时不能达到“通过”状态。
5. 预览与 MP4 导出使用同一可见性判定。
6. 检测只报告问题，不擅自改写用户或 AI 生成的动画脚本。

## 4. 非目标

- 不把自动优化认定为本次脚本错误的来源。
- 不用正则批量改写所有历史分镜。
- 不强制所有元素在首帧显示。
- 不禁止正常的淡入、渐进显示和退场动画。
- 不将装饰元素、字幕或明确标记为隐藏的元素计入核心可见性。

## 6. 对接协议

### 6.1 静态校验协议

在 `validateGeneratedHtml()` 中增加动画生命周期校验。

第一期只拦截可以确定为错误的模式：

```js
target.addEventListener(eventName, callback);
target.removeEventListener(eventName, callback);
```

同时满足以下条件才报错：

- `target`、`eventName`、`callback` 相同。
- `removeEventListener` 位于注册后的同一执行作用域。
- 两者之间没有进入清理函数、卸载回调或其他延迟执行作用域。
- `removeEventListener` 会在目标事件触发前同步执行。

错误信息：

```text
Animation lifecycle removes the load listener before it can run.
```

处理规则：

- 首次生成：作为 `HtmlValidationError` 交给现有重试链路重新生成。
- AI 质量修复：拒绝候选 HTML，保留修复前版本。
- 手动编辑保存：返回可理解的中文错误，不覆盖现有版本。
- 静态校验只拒绝，不自动删除或移动脚本语句。

### 6.2 运行态可见性协议

复用现有 iframe 最终布局检查点：

```js
setTimeoutOrig(auditLayout, Math.min(WATCHDOG_MS + 100, 2200));
```

在 `auditLayout()` 中增加核心视觉可见性检查。

候选元素范围：

```text
[data-role="visual-zone"] [data-editor-id]
[data-role="visual-zone"] [data-element-id]
[data-role="visual-content"] [data-role="composite"]
```

排除：

- `data-role="decoration"`
- `aria-hidden="true"`
- `hidden`
- 没有实际尺寸的空容器
- 字幕和编辑器覆盖层

元素可见条件必须同时满足：

```text
rect.width >= 4
rect.height >= 4
与 1280×720 画布存在交集
自身及祖先 display != none
自身及祖先 visibility != hidden
自身及祖先累计 opacity > 0.1
```

判定规则：

- 候选元素数量为 0：不在本规则中报错，交由现有结构校验处理。
- 候选元素存在，且至少一个核心元素可见：通过本规则。
- 候选元素存在，但核心元素全部不可见：新增严重问题。

返回结构复用现有 `LayoutIssue`：

```ts
{
  code: 'invisible',
  severity: 'critical',
  label: '核心画面未显示',
  detail: '视觉区包含元素，但在动画最终检查点仍全部透明或不可见。',
  elementId: 'visual-content'
}
```

该问题不提供 `suggestedFix`。原因是坐标、缩放或透明度的机械修改可能破坏原动画，正确处理方式是修复脚本或重新生成当前镜头。

### 6.3 质量评分协议

`autoOptimizeFrame()` 继续使用现有评分逻辑：

- `invisible + critical` 扣除严重问题分值。
- `qualityPassed()` 检测到任意 `critical` 时返回 `false`。
- 最终状态必须为 `needs_review`，不能保存为 `passed`。
- 质量报告中的 `htmlHash` 必须对应实际被检查的 HTML。

无需修改 Prisma schema。`FrameQualityReport.issues` 已能持久保存 `LayoutIssue`。

质量面板展示建议：

```text
标题：核心画面未显示
说明：元素已生成，但动画没有把它们切换到可见状态。
建议：修复动画启动脚本，或重新生成当前分镜。
```

### 6.4 预览兜底协议

预览发现 `invisible` 时：

- 保持标题和当前可见内容，不修改数据库。
- 在质量面板显示严重问题。
- 分镜缩略图显示问题数量。
- 不自动给所有透明元素设置 `opacity: 1`。
- 用户仍可进入画面编辑、重新生成或手动修复。

可选的第二期兜底：

- 仅在预览中提供“临时显示静态终态”按钮。
- 临时显示只作用于当前 iframe，不写回 `htmlCode`。
- UI 必须明确标记“临时预览，不代表动画已修复”。

### 6.5 导出协议

MP4 导出不能仅依赖历史质量报告，因为 HTML 可能在报告生成后发生变化。

导出每镜加载完成后执行与预览一致的最终可见性检查：

```ts
type RenderVisibilityStatus = {
  checked: boolean;
  candidateCount: number;
  visibleCount: number;
  issue?: 'invisible';
};
```

处理规则：

- `visibleCount > 0`：继续编码。
- `candidateCount > 0 && visibleCount === 0`：该镜标记失败并停止最终拼接。
- 错误信息：`第 N 镜包含视觉元素，但动画结束检查时仍全部不可见。`
- 已完成分镜缓存继续保留，修复后只重试失败镜头。

预览和导出必须调用同一份判定函数或注入同一段运行时代码，禁止维护两套可见性标准。

## 7. 第 29 镜修复方式

将监听逻辑改为：

```js
if (document.readyState === 'complete') {
  startAnimation();
} else {
  window.addEventListener('load', startAnimation, { once: true });
}
```

同时使 `startAnimation()` 幂等：

```js
let started = false;

function startAnimation() {
  if (started) return;
  started = true;
  // 原动画逻辑
}
```

不得在注册后同步调用：

```js
window.removeEventListener('load', startAnimation);
```

如果确实需要清理，应放在组件销毁或明确的清理回调中；当前独立分镜文档不需要主动清理一次性 `load` 监听。

## 8. 测试清单

### 8.1 静态校验

| 用例 | 预期 |
| --- | --- |
| 注册 `load` 后立即移除相同回调 | 校验失败 |
| 使用 `{ once: true }` 注册 | 校验通过 |
| 在真正的清理函数中移除 | 校验通过 |
| `DOMContentLoaded` 正常启动 | 校验通过 |
| 页面已完成时直接启动 | 校验通过 |

### 8.2 运行态检查

| 用例 | 预期 |
| --- | --- |
| 元素初始透明，500ms 后显示 | 通过 |
| 元素初始透明，1500ms 后显示 | 通过 |
| 2200ms 后核心元素仍全部透明 | 返回 `invisible/critical` |
| 只有装饰元素透明 | 不报核心不可见 |
| 核心元素父容器 `opacity: 0` | 返回 `invisible/critical` |
| 核心元素在画布外 | 继续由 `out_of_bounds` 报告 |
| `prefers-reduced-motion` 显示静态终态 | 通过 |

### 8.3 回归样本

必须把第 29 镜保存为测试夹具，至少验证：

- 修复前：四个 `.circle-layer` 最终均为 `opacity: 0`，审计失败。
- 修复后：四个元素获得 `.active`，至少一个核心元素可见。
- 点击“重新开始”后动画可再次播放。
- 缩略图、主预览和导出画面不出现全空视觉区。

## 9. 实施顺序

1. 修复第 29 镜并人工确认预览。
2. 在 `iframe-utils.ts` 落地运行态 `invisible` 检查。
3. 增加质量评分和质量面板回归测试。
4. 在 `html.ts` 增加确定性动画生命周期静态校验。
5. 将同一检查接入 Render Worker。
6. 扫描已有项目并只生成问题清单，不批量改写。
7. 完整运行 TypeScript、Vitest、浏览器预览和单镜导出验证。

## 10. 验收标准

- 第 29 镜四层元素在主预览中按顺序出现。
- 修复后控制台无相关运行错误。
- 原故障 HTML 被识别为 `invisible/critical`。
- 原故障 HTML 不能获得 90 分以上或 `passed` 状态。
- 正常渐进动画不会被误判。
- 关闭“生成后逐镜自动优化”时，预览和导出安全检查仍然有效。
- 预览与 MP4 导出对同一 HTML 给出一致结果。
- 所有新增和现有测试通过。
