# AI Video Agent 协作规范

本文件约束在 `ai-video-agent` 中工作的所有 AI Agent 与开发者。目标是在保证可维护性、可验证性和用户数据安全的前提下迭代 AI 视频创作工作台。

## 项目边界

- 技术栈：Next.js 14 App Router、React 18、TypeScript、Tailwind CSS、Prisma/MySQL、Vitest。
- 主要业务链路：用户需求 → 意图识别/大纲 → 分镜 → 图片或 HTML 动画画面 → 配音与字幕 → 预览/单镜调整 → MP4 导出。
- 前端代码位于 `src/components`、`src/app` 与 `src/hooks`；服务端 API 位于 `src/app/api`；领域逻辑位于 `src/lib`；数据库模型及迁移位于 `prisma`；自动化测试位于 `tests`。

## 工作方式

1. 先阅读相关实现、类型、API 路由和现有测试，再做最小且完整的改动；不要为无关问题重构代码。
2. 保持 TypeScript 类型完整。跨层数据结构发生变化时，同步更新 `src/types`、调用方、API 校验和测试。
3. 优先复用 `src/lib` 的业务能力和既有 UI 组件；不要复制提示词、环境变量解析、媒体存储或错误处理逻辑。
4. 对耗时生成任务保留取消、中断恢复和进度反馈能力；不要把密钥、原始 API 响应或用户私有内容输出到客户端日志。
5. 修改 Prisma schema 时，同时提供匹配的 migration，并确认本地开发/部署路径是否需要更新。
6. 不提交 `.env`、API Key、生成的音频图片视频、数据库文件或其他运行时产物。新增环境变量必须同步更新 `.env.example` 和 README。

## 视频与媒体约束

- 图片模式和 HTML 模式均须维持现有分镜数据契约；不能让一种模式破坏另一种模式的预览或导出。
- **DeepSeek 不具备本项目所需的视觉能力。** DeepSeek 仅可用于意图识别、大纲、脚本、分镜文字和其他纯文本任务；不得将其配置为图片生成、视觉理解、画面评审、视觉锚点或图文多模态任务的模型。此类任务必须使用具备相应视觉能力的模型或既有图片服务。
- 调整字幕、音频、时长、画面尺寸或播放器逻辑时，检查预览与 MP4 导出的一致性。
- 外部图片搜索、联网研究和 TTS 均应有可理解的失败提示和安全降级，且不得阻塞已完成的分镜使用。
- 涉及画面质量、排版或视觉锚点的变更，优先补充对应的单元/组件测试；必要时人工检查预览结果。

## README 强制维护

`README.md` 是项目当前能力的唯一公开说明，必须与代码保持一致。

- **每次改变程序行为、用户可见功能、使用流程、配置、接口或运行命令时，必须在同一个改动中同步更新 `README.md`。**
- 新增、移除或明显调整功能时，更新 README 的“当前功能清单”；新增配置时更新环境变量表和示例；更改流程或命令时更新对应说明。
- README 只描述已在当前代码中实现且可使用的能力，不写计划中、猜测中或已移除的功能。
- 若改动完全不影响功能、配置、操作方式或项目结构，可在交付说明中明确“README 无需更新”及原因。
- 完成前检查 `git diff`，确认代码改动与 README 说明一致；README 与功能不同步时不得视为任务完成。

## 验证与交付

1. 为行为变更新增或更新相关 Vitest 测试；至少运行与改动最接近的测试。可行时运行 `npm test`，构建/类型相关变更再运行 `npm run build`。
2. 如果验证因环境、外部服务或既有失败而无法完成，明确报告未运行项、失败原因及影响范围，不要伪称通过。
3. 交付时简述功能变化、README 更新位置、验证命令及结果，并列出仍需用户配置的外部依赖。
