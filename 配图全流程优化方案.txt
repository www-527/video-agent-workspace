配图全流程优化方案

目标

把“配图”变成视频叙事的一部分：既不把图库图硬塞进每镜，也不让检索等待拖慢整条视频生成。

总体流程

脚本 / 大纲
→ 分镜导演：视觉策略
→ 配图规划：选镜、用途、检索词、构图
→ 镜头级任务队列
→ Pexels 检索与候选评分，同时进行 TTS 合成
→ 素材合格且及时：生成带真实图的 HTML 镜头
→ 素材不合格、超时或不可用：生成原生动画镜头
→ 视觉质检、保存来源
→ 预览 / 导出视频

一、分镜阶段：先定义“视觉职责”，再决定是否找图

每个镜头除 assetStrategy 外，增加 visualRole：

- context：交代场景、地点、行业氛围
- human-proof：展示人正在做什么，建立代入感
- physical-proof：设备、空间、自然或实体对象
- explain：数据、因果、流程、对比
- emphasis：标题、结论、金句、数字
- transition：章节呼吸与节奏切换

规则：

- context / human-proof / physical-proof 才有资格进入真实素材候选池。
- explain / emphasis / transition 固定使用原生 HTML、图表、排版或图标，不搜索真实图。
- assetStrategy=real-image 是强建议而非强制执行；最终由配图规划器根据全片节奏决定。

建议新增字段：

visualRole: 'context' | 'human-proof' | 'physical-proof' | 'explain' | 'emphasis' | 'transition'
realImagePriority: 'required' | 'preferred' | 'optional' | 'never'
imagePurpose?: '建立场景' | '证明人物状态' | '呈现实物参照'

二、全片配图规划：一次轻量决策，不做下载

在首镜定调确认后，单次 AI 调用产出全片 ImagePlan。它负责全局一致性，不直接调用 Pexels。

每个候选镜头输出：

{
  frameId,
  useRealImage: true,
  priority: 80,
  purpose: '建立真实办公场景',
  query: 'product team meeting modern office',
  fallbackQueries: ['creative team collaborative workspace'],
  layout: 'editorial-split',
  textPosition: 'left',
  imageMotion: 'slow-push-in',
  visualGroup: 'workplace',
  deadlineMs: 10000
}

全局约束建议：

- 默认真实图占 20–35%，而不是固定 20–40%。
- 4 镜以内最多 1 张；5–8 镜最多 2 张；之后按约 1/3 估算。
- 最多连续 2 镜真实图，优先控制为真实图后至少一镜信息动画。
- 同一 visualGroup 保持相近色温、题材和空间关系。
- 开场允许强真实图或强原生视觉二选一；结尾优先结论型原生画面。
- 具名人物、品牌、具体产品、新闻事件一律 never，除非未来接入可验证的授权素材源。

三、素材检索：候选、评分、下载三段式

不要“搜到就下载”，改为：

1. 以主检索词、备用检索词分别拿候选。
2. 先在内存中筛选、打分，保留每镜 3 个候选。
3. 仅下载第一名；下载失败或不合格，再尝试后备候选。

评分维度：

- 主体匹配：人、场景、设备是否与镜头职责吻合。
- 构图匹配：是否能给文案留出安全区。
- 横竖与分辨率：是否适合 16:9 画面裁切。
- 风格一致性：色温、摄影风格是否贴近相邻真实图。
- 重复惩罚：避免同一张图、同一摄影师、相似构图连续出现。
- 信息风险：画面中是否有明显品牌、不可控文字、误导性上下文。

新增一次轻量“素材验收”：

- 图片下载后，通过视觉模型或规则检查主体、构图、文字安全区。
- 不通过则自动换下一候选。
- 不让生成 HTML 的模型承担素材甄别职责。

四、调度：由全局阻塞改为镜头级流水线

当前问题：全部配图准备完成后，才开始镜头生成。

目标：

全片快速规划完成
→ #1 配图检索 + #1 TTS 并行
→ #2 配图检索 + #2 TTS 并行
→ #1 素材到位：立即生成带图 HTML
→ #2 素材超时：立即生成原生 HTML
→ 后续镜头持续滚动

建议并发上限：

- 配图检索：2
- 图片下载 / 验收：2
- HTML 生成：2
- TTS：3–4

每镜设置素材等待预算：

- 推荐模式：10 秒
- 快速模式：5 秒
- 素材优先模式：20 秒

到时仍无合格图，镜头立刻降级为原生动画；不让一张图拖住整个视频。

五、HTML 生成：让图片成为画面的一部分

给 HTML 模型的输入不只包含本地路径，还应包括素材职责和镜头语法：

realImage: {
  localPath,
  alt,
  layout,
  textPosition,
  fitMode,
  imageMotion,
  purpose,
}

渲染约束：

- full-bleed：适合纯场景，文案压在空白侧，缓慢推拉。
- editorial-split：图片与信息区分栏，适合解释型叙事。
- framed-focus：人物或设备使用裁切卡片，并配标注或数据。
- 每张真实图至少有一种信息关系：标签、关键词、数据、前后动画衔接；禁止只作无意义背景。
- 连续真实图片之间必须改变构图或运动方向，避免幻灯片感。

六、降级、重试与数据一致性

每个镜头维护状态：

planned → searching → candidate_ready → downloading
→ accepted → rendering_with_image → completed
                  └→ timed_out / rejected / unavailable
                     → rendering_native → completed

原则：

- 搜索失败、429、下载失败、素材验收失败都只影响当前镜头。
- 成功生成 HTML 且实际引用本地图片后，才保存 realImage(s) 到项目状态。
- 记录可读失败原因：无匹配素材、主体不符、无文案安全区、服务限流、超时降级。
- 重新生成某镜头时，默认复用已验收素材；用户选择“换图”才重新搜索。

七、用户体验

将“智能配图”开关升级为策略选择：

- 快速：少量真实图、5 秒超时、优先出片。
- 平衡（默认）：20–35% 真实图、10 秒超时。
- 素材优先：更多真实场景、20 秒超时，适合品牌感或纪录感内容。

生成时显示镜头级状态，而非笼统的“正在配图”：

#3 真实素材匹配中
#1 已完成：原生数据动画
#2 已完成：办公场景素材 + 信息叠层
#4 未找到合格素材，已自动采用动画设计

完成页提供“素材来源”和“配图决策”：

- 哪些镜头用了真实图、其叙事目的。
- 哪些镜头主动没用图、原因。
- 摄影师与 Pexels 来源。
- 单镜“换图 / 改为动画 / 强制配图”操作。

八、实施顺序

第一期：先解决等待体验，不改变选图质量。

1. 将当前全局 prepareSmartImages() 拆成“全局 planRealImages() + 单镜素材准备”。
2. 在 HTML 主流程中，让 TTS、单镜素材准备和 HTML 渲染形成流水线。
3. 加入每镜超时降级与镜头级进度。

第二期：提升配图质量。

4. 扩展 ImagePlan，加入 purpose / visualGroup / imageMotion / priority。
5. 引入候选缓存、视觉一致性评分和下载后验收。
6. 完善“换图”和配图决策可视化。

第三期：策略产品化。

7. 增加快速 / 平衡 / 素材优先模式。
8. 按用户“保留 / 换图 / 改动画”的行为，逐步校正默认比例与选图偏好。

结论

全片先统一决策，镜头再独立执行；素材是可超时降级的增强项，而不是生成视频的硬前置条件。
