Pexels 图片搜索功能实施计划
============================

一、功能目标
------------

在 HTML 动画模式中增加“图片搜索”按钮，由 Agent 自动判断哪些分镜需要真实图片，调用 Pexels API 搜索素材，根据元数据和质量规则筛选图片，下载到本地，再将图片融入对应的 HTML 分镜。

该功能只用于 HTML 模式。图片轮播模式不显示此按钮。

完整流程：

1. 用户完成内容计划并进入 HTML 模式。
2. 用户点击“图片搜索”。
3. Agent 分析全部分镜，决定哪些分镜适合使用真实图片。
4. Agent 为选中的分镜生成英文检索词和备用检索词。
5. 服务端调用 Pexels API 搜索候选图片。
6. 程序通过元数据、分辨率、画幅比例和去重规则自动评分。
7. 下载最佳候选图片到项目本地。
8. 重新生成或更新受影响的 HTML 分镜，将图片融入构图。
9. 保留已有旁白音频，不重复生成 TTS。
10. 保存摄影师、Pexels 页面和检索词等来源信息。


二、现有项目可复用能力
----------------------

当前项目已经具备以下基础：

1. SceneSpec 已包含 assetStrategy，可取 real-image、icon、chart、typography 或 css-svg。
2. 编导层已经可以初步判断人物、地点、建筑和产品外观等内容应使用 real-image。
3. HTML 生成提示词已有 real-image 占位规则。
4. HTML 安全校验会禁止外部 HTTP 资源，适合采用“服务端下载、本地加载”的安全方案。
5. /api/data 已能提供 data 目录中的本地图片。
6. videoSource 是 JSON 字段，可以保存真实图片信息，第一版不需要进行 Prisma 数据库迁移。


三、按钮和使用流程
------------------

按钮名称：图片搜索

建议位置：HTML 模式顶部工具栏，靠近“一键生成其余镜头”。

显示条件：

- project.type === "html"
- project.outline 已存在
- 内容计划已经确认
- 当前没有其他生成任务

点击按钮后运行一条服务端 SSE 流程，界面依次显示：

- 分析分镜
- 规划真实素材
- 搜索图片
- 筛选候选
- 下载素材
- 更新 HTML
- 保存结果
- 完成

完成提示示例：

已分析 12 个分镜，选择 4 个分镜使用真实图片，成功下载 4 张，已更新 4 个 HTML 画面。

再次点击时默认只补齐缺失图片，不重复请求已有结果。后续可以在单镜操作中增加“重新搜索本镜图片”。


四、Agent 判断哪些分镜需要图片
------------------------------

不能给每个分镜机械配图。真实图片只用于它能明显增加可信度、代入感或具体感的地方。

适合使用真实图片：

- 具体人物、职业和生活状态
- 人物情绪与社会场景
- 城市、地点、建筑和自然环境
- 产品外观、实体设备和真实空间
- 真实案例、行业现场和工作环境
- 需要增强可信度或现实感的内容

不适合使用真实图片：

- 流程、因果和层级结构
- 数据、比例和趋势
- 抽象概念
- 金句、标题和总结
- HTML 图表、CSS 或 SVG 能表达得更清楚的内容
- 只能找到泛化装饰图、无法证明旁白内容的分镜

全片密度约束：

- 建议只有 20% 至 40% 的分镜使用真实图片。
- 连续真实图片最多两镜。
- 同一张 Pexels 图片不能重复使用。
- 相似检索主题不能长时间连续出现。
- 找不到合格素材时保留 HTML 原生画面，不强行配图。
- 每镜只允许一个主要视觉焦点，第一版不做多图拼贴。

Agent 输出建议采用结构化 JSON：

{
  "frameId": "frame-3",
  "useRealImage": true,
  "reason": "需要展示真实办公环境和人物状态",
  "query": "stressed office worker multiple screens late night",
  "fallbackQuery": "overwhelmed employee computer office",
  "subject": "office worker",
  "composition": "editorial-split",
  "textPosition": "left"
}

DeepSeek 不负责识别图片内容，只负责理解旁白、决定是否需要图片、生成检索词和选择构图策略。


五、Pexels API 搜索
------------------

接口：

GET https://api.pexels.com/v1/search

请求头：

Authorization: PEXELS_API_KEY

建议参数：

- query：Agent 生成的英文检索词
- orientation=landscape
- size=large
- locale=en-US
- per_page=15

每个目标分镜通常只发起一次搜索。如果没有结果或所有候选都不达标，才使用 fallbackQuery 再搜索一次。

需要读取并记录以下限额响应头：

- X-Ratelimit-Limit
- X-Ratelimit-Remaining
- X-Ratelimit-Reset

搜索词应进行小写化、去除多余空格等规范化，并将搜索结果缓存 24 小时，降低 API 调用次数。


六、元数据筛选和评分
--------------------

DeepSeek 不能识图，因此第一版使用确定性元数据评分，不假装进行视觉理解。

评分建议：

1. 搜索相关度，40 分
   - Pexels 返回排名
   - alt 字段与主体关键词的覆盖程度

2. 视频画幅适配，25 分
   - 图片比例是否接近 16:9
   - 是否适合全屏或分栏布局

3. 清晰度，20 分
   - 原图宽高
   - 可下载尺寸
   - 是否满足视频分辨率要求

4. 全片去重，10 分
   - photoId 不重复
   - 同一摄影师不连续使用
   - 相同 alt 或相同主题不过度重复

5. 色彩协调，5 分
   - 使用 avg_color 避免连续画面颜色过度雷同
   - 不依赖颜色判断图片语义

候选淘汰规则：

- 宽度不足 1280 像素时直接淘汰。
- 优先选择宽度达到 1920 像素的图片。
- 图片比例与预定布局严重不匹配时淘汰。
- alt 与检索主体完全无关时淘汰。
- photoId 已在当前项目使用时淘汰。
- 下载地址、MIME 或文件体积不符合要求时淘汰。


七、图片尺寸和视频画幅适配
--------------------------

当前 HTML 视频设计舞台为 1280×720，比例为 16:9。图片适配必须由规则确定，不能直接拉伸。

通用原则：

- 永远保持图片原始宽高比。
- 禁止使用 width 和 height 强行拉伸造成变形。
- 优先使用 Pexels large2x 或足够清晰的原始资源。
- 原图宽度低于 1280 像素时不使用。
- 预览、回放和导出必须使用同一套适配参数。

不同画幅处理：

1. 接近 16:9 的横图
   - 使用 object-fit: cover。
   - 允许少量边缘裁切。
   - 可以作为全屏背景或大面积主体图。

2. 普通横图，但与 16:9 有一定偏差
   - 优先使用 editorial-split 左右分栏。
   - 减少裁切，保留主体完整性。

3. 超宽图片
   - 使用居中裁切或非常缓慢的横向移动。
   - 不允许快速平移。

4. 竖图或方图
   - 不允许强行全屏铺满。
   - 使用 object-fit: contain。
   - 配合深色、主题色或模糊背景。
   - 或放入左右分栏中的图片区域。

5. 低分辨率图片
   - 自动选择下一候选图。
   - 不通过大幅放大掩盖清晰度问题。

建议为每张素材保存适配参数：

{
  "fitMode": "cover",
  "position": "center",
  "layout": "editorial-split",
  "scaleFrom": 1.02,
  "scaleTo": 1.06
}

第一版统一使用 object-position: center。因为 DeepSeek 不识图，不能可靠判断人物位于左侧还是右侧。通过优先选宽图、控制裁切幅度、比例偏差时使用分栏布局，减少裁掉主体的概率。


八、本地下载和安全策略
----------------------

不要让生成的 HTML 直接引用 Pexels 外链。服务端先下载，HTML 只读取本地资源。

本地目录：

data/pexels/<projectId>/<frameId>-<photoId>.jpg

浏览器路径：

/api/data/pexels/<projectId>/<frameId>-<photoId>.jpg

下载规则：

- 最大文件体积 15 MB。
- 设置请求超时。
- 只接受 JPEG、PNG 和 WebP。
- 检查响应 MIME。
- 文件名只使用项目 ID、分镜 ID 和 Pexels 图片 ID。
- 禁止路径穿越。
- API Key 只允许服务端读取。
- 日志不得输出 API Key。
- HTML 中禁止出现 Pexels 图片下载外链。


九、数据结构
------------

建议新增：

interface RealImageAsset {
  provider: 'pexels';
  photoId: number;
  localPath: string;
  query: string;
  alt: string;
  width: number;
  height: number;
  avgColor?: string;
  photographer: string;
  photographerUrl: string;
  pexelsUrl: string;
  fitMode: 'cover' | 'contain';
  position: 'center';
  layout: 'full-bleed' | 'editorial-split' | 'framed-focus';
  scaleFrom: number;
  scaleTo: number;
  downloadedAt: string;
}

在 FrameSource 中增加：

realImage?: RealImageAsset

由于 videoSource 是 JSON 字段，第一版可以直接保存该结构，不需要数据库迁移。


十、图片融入 HTML 的方式
------------------------

给 generateFrameHtml 增加 realImage 参数。如果存在真实图片，应向模型传入固定的本地路径、alt 和构图策略。

示例提示：

本镜已提供真实图片：
路径：/api/data/pexels/...
构图：editorial-split
必须使用该本地路径，不得创建外链，不得替换图片。

只开放三种稳定构图：

1. full-bleed
   - 图片铺满画面。
   - 只适用于接近 16:9、画面信息简单、屏幕文字很少的素材。

2. editorial-split
   - 图片与文字左右分栏。
   - 默认推荐，稳定、清晰，能够减少人物被裁切或被字幕遮挡的问题。

3. framed-focus
   - 图片作为中央视觉主体，周围保留充分留白。
   - 适合竖图、方图或产品图。

动画规则：

- 图片缩放一般从 1.02 到 1.06。
- 一镜只使用一种缓慢运动。
- 禁止大幅旋转、弹跳和快速缩放。
- 不做无意义的复杂视差。
- 图片上叠加文字时增加克制的主题色或暗色遮罩。
- 禁止圆角卡片墙和多图拼贴。

HTML 硬校验：

- realImage 存在时，HTML 必须包含指定 localPath。
- 只允许加载 /api/data/pexels/ 下的图片。
- 图片必须位于 visual-zone。
- 图片必须包含 alt。
- 禁止任何外部图片 URL。
- 未使用指定图片时自动重试一次 HTML 生成。

如果 HTML 已经生成，图片搜索完成后只重新生成受影响分镜的 htmlCode，保留已有 audioPath 和 audioDuration。

--------------------

- Pexels 图片页面

该署名不必强制压在每一个视频画面上，但应用界面中应该能够清晰查看素材来源，并提供返回 Pexels 的链接。


十三、错误处理
--------------

1. 未配置 PEXELS_API_KEY
   - 按钮提示“尚未配置 Pexels API”。

2. 401
   - 提示 API Key 无效，不修改现有项目。

3. 429
   - 显示额度耗尽和重置时间，停止继续搜索。

4. 搜索无结果
   - 使用备用检索词重试一次。
   - 仍无结果则保留原 HTML 画面。

5. 下载失败
   - 尝试下一候选图片。

6. HTML 更新失败
   - 保留原 htmlCode 和已下载素材。
   - 不破坏旁白音频。

7. 用户中断
   - 停止新的搜索和 HTML 生成。
   - 已成功保存的结果继续保留。


十四、实施顺序
--------------

阶段 1：配置和 Pexels 客户端

- env.ts 读取 PEXELS_API_KEY。
- 建立请求类型、响应类型和授权请求。
- 处理错误码和限额响应头。
- 编写客户端单元测试。

阶段 2：Agent 图片规划

- 建立 real-image-planner。
- 输入整片分镜、SceneSpec 和导演计划。
- 输出 useRealImage、查询词、原因和构图。
- 加入 20% 至 40% 密度及连续镜头约束。

阶段 3：搜索、评分、缓存和下载

- 调用 Pexels 搜索。
- 实现元数据评分和候选淘汰。
- 实现 24 小时缓存。
- 下载到 data/pexels。
- 保存来源和适配信息。

阶段 4：HTML 集成

- 将 realImage 传入 generateFrameHtml。
- 增加三种图片构图协议。
- 增加缩放、裁切和安全规则。
- 增加指定本地图片路径硬校验。

阶段 5：API 和按钮

- 增加图片搜索 SSE 接口和中断接口。
- HTML 模式工具栏增加“图片搜索”。
- 增加进度、错误和完成摘要。

阶段 6：来源信息与单镜重搜

- 增加素材来源入口。
- 增加单镜“重新搜索图片”。
- 支持重新搜索时保留旁白。

阶段 7：测试和质量验收

- 运行单元测试、集成测试和 TypeScript 检查。
- 使用完整 HTML 视频项目进行预览、刷新、回放和导出测试。


十五、测试范围
--------------

单元测试：

- Pexels 请求是否带 Authorization。
- API Key 不进入客户端代码和日志。
- 查询参数是否正确编码。
- 元数据评分和分辨率淘汰是否正确。
- 16:9、普通横图、超宽图和竖图的布局选择是否正确。
- 同一图片是否会被去重。
- Agent 输出异常时是否能安全降级。
- HTML 是否只接受本地图片路径。

集成测试：

- 模拟 Pexels 搜索和图片下载。
- 图片信息是否保存到 videoSource。
- 更新 HTML 时是否保留已有 TTS。
- 页面刷新后图片是否仍能显示。
- 401、429、空结果和下载失败是否安全降级。
- 重复点击是否使用已有结果和缓存。

界面测试：

- 图片模式不显示按钮。
- HTML 模式在正确阶段显示按钮。
- 搜索过程中按钮不可重复点击。
- 进度和完成摘要正确。
- 素材来源可以查看。


十六、最终验收标准
------------------

- “图片搜索”只出现在 HTML 模式。
- 用户点击一个按钮即可完成判断、搜索、下载和 HTML 更新。
- Agent 自主决定哪些分镜需要图片。
- 10 镜视频通常只使用 2 至 4 张真实图片。
- 连续真实图片不超过两镜。
- 没有合适图片时保持 HTML 原生画面。
- 图片保持宽高比，不发生拉伸变形。
- 低分辨率图片不会进入视频。
- 竖图和方图不会被粗暴铺满裁切。
- 预览、回放和导出使用相同的缩放参数。
- 页面刷新后本地图片仍然存在。
- HTML 中不存在 Pexels 图片外链。
- 重新搜索图片不会重新生成旁白。
- API Key 不会进入浏览器、数据库内容或日志。
- Pexels 素材能够追溯到摄影师和原始图片页面。
- 任一分镜搜索失败都不会破坏已有视频。
